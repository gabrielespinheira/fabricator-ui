# File icons pack: plan

A third data shape for Fabricator Icons, after icons and brands (I5 in `icon-pack.md`): colour icons for files and folders, picked by name, the set Relay's explorer draws. File Tree uses it for its default icons.

## Source

Relay vendors [Charmed Icons](https://github.com/littensy/charmed-icons) v0.10.0 (commit `4b004b2`, MIT, © 2024 Littensy) with `relay/scripts/vendor-charmed-icons.ts`.

- 249 SVGs on a 16×16 grid: 116 file icons, 65 named folders each with an `_open` twin, plus `_file`, `_folder` and `_folder_open`.
- 37 distinct paints, mostly from `scripts/palettes.ts`, plus four explicit art colours. No gradients, images or text. Two icons use masks; viewport clips and one-shape opacity groups are flattened with a pixel comparison.
- Palettes: `base` (dark surfaces) and `light`, which overrides 22 of the 34 colours with the same shapes. `soft` and `warm` exist and are out of scope.
- Associations: `src/defaults/file-icons.ts` (file names, extensions, ~1,100 lines) and `folder-icons.ts`. Relay flattens them into `fileNames`, `fileExtensions` and `folderNames` maps, lower-cased, with a lookup that tries the full name, then each extension from the first dot (`a.test.ts` → `test.ts` → `ts`).
- Size: 489 KB of SVG, 119 KB gzipped, before any path minification. Per-icon components tree-shake like the other packs.

## Decisions

1. **Vendored, pinned, regenerated by a script.** `bun run icons:files --ref v0.10.0` writes `packages/icons-core/sources/files/` (SVGs, the association maps, the notice), records the commit in `icons.lock.json`, and fails if the checkout isn't at the pinned commit. Same pattern as `icons:sync` and `icons:animated`.
2. **Palette colours become CSS variables.** Every fill is rewritten from a hex to `var(--file-icon-<colour>)`. The pack ships the variables with `light-dark(<light>, <base>)` values, so one SVG follows the theme. A project can retint the set by overriding the variables; nothing else in Fabricator needs to know the palette. React Native resolves the same palette through the icon package's existing `IconProvider` colour scheme.
3. **Exports.** `@fabricator-ui/icons/files`:
   - `FileTypeIcon({ name, kind: "file" | "folder", open, size, ...svgProps })`, the one component an explorer needs.
   - `getFileIconName(fileName)`, `getFolderIconName(folderName, open)`, pure and tested (the lookup above).
   - Each icon as a component too (`FileTypescriptIcon`, `FolderComponentOpenIcon`…) for direct use.
   - The same subpath in `@fabricator-ui/icons-react-native`, and SVG files plus a sprite in `@fabricator-ui/icons-static`.
4. **File Tree uses it by default.** The registry item adds the npm dependency `@fabricator-ui/icons`; the default `FileTreeIcon` renders `FileTypeIcon`, and `renderIcon` stays for any other set. The current `IconPlaceholder` folders with badges are removed. This makes File Tree the one item whose icons ignore the project's `iconLibrary`, which is right: Lucide, Tabler and the rest have no file-type set, and the explorer look depends on it.
5. **Site.** A "Files" tab on `/icons` beside Brands, with the association table searchable by file name. Docs page under `content/docs/icons/`.
6. **Attribution.** Charmed's licence in `packages/icons/LICENSE.md` and `NOTICE.md`, as with Lucide.

## Phases

1. Import script, sources, lock entry, palette-to-variable rewrite with tests (every fill maps to a palette name; light and base resolve; no hex left).
2. React subpath, lookup functions (tests ported from Relay's `file-icons` cases), size budget in `scripts/size.ts`.
3. File Tree switches to it; docs, demos and the Fabricator `DESIGN.md` entry follow; registry build and `shadcn add --dry-run` per base.
4. React Native and static outputs; `/icons` Files tab.
5. Changeset for the icon packages; release with `bun run release:icons`.

## Risks

- **Colour contrast.** Charmed's light palette was drawn for VS Code's white; Fabricator's light surfaces are tinted. Light and dark contact sheets were inspected. Some decorative fills have low contrast on light surfaces; filenames remain the accessible label, and the tree marks the icons decorative. Retint through the variables when artwork must carry meaning on its own.
- **Upstream cadence.** Charmed is a one-person project; the last tag is May 2025. Vendoring at a pin means a stalled upstream costs nothing.
- **Bundle.** `FileTypeIcon` needs the whole map and every icon it can return (about 138 KB minified and gzipped, including associations). Lazy chunks per icon would add a flash on first render; ship it eager and state the size in the docs.

## Implemented

The pack ships through `/files` in the three existing icon packages. File Tree uses `FileTypeIcon`; the `/icons` gallery has a Files tab, filename search and exports. Theme paint has inline CSS-variable fallbacks, so consumers need no extra stylesheet. Native uses `IconProvider` and the same palette data. Static output includes theme-aware SVGs, explicit light/dark SVGs and a sprite. Changeset prepared; publishing is a separate release.
