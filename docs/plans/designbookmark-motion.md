# Motion study: designbookmark.com/motion

A study of the 89 animated components on https://designbookmark.com/motion (captured 26 Nov 2026), what makes their motion feel good, and how to bring it into Fabricator UI. No component code yet; this plan decides what gets built and in what order.

Evidence lives in `.reanimate/designbookmark-motion/` (gitignored): the full source of every component (`ref/source/`), the shared tokens and spring engine (`ref/shared/`), per-component motion facts (`ref/facts/`), and a 7 s autoplay capture with a filmstrip per component (`ref/cards/<slug>/sheets/`).

## The motion system behind it

One engine (`ref/shared/motion.js`): a spring is `{ x, v, target, stiffness k, damping c }` with mass 1, integrated with semi-implicit Euler, 4 substeps per frame, frame time capped at 1/30 s. Timers run on the same simulated clock, so the gallery's slow-motion switch slows timers and springs together. Under `prefers-reduced-motion` every spring is retuned to critical damping (`c = 2√k`): same speed, no overshoot.

Shared presets from `tokens.css`, simulated with that engine:

| Preset    | k / c    | Damping ratio | Overshoot | Reaches 98 % | Settles (0.5 %) | Used for                                     |
| --------- | -------- | ------------- | --------- | ------------ | --------------- | -------------------------------------------- |
| `follow`  | 900 / 50 | 0.83          | 0.3 %     | 142 ms       | 158 ms          | anything held by the pointer                 |
| `settle`  | 280 / 22 | 0.66          | 5.7 %     | 175 ms       | 396 ms          | letting go, landing on a value               |
| `soft`    | 260 / 24 | 0.74          | 2.4 %     | 213 ms       | 433 ms          | panels, sheets, the whole component shifting |
| `lead`    | 620 / 36 | 0.72          | 2.8 %     | 133 ms       | 275 ms          | stretchy highlight, the edge facing the move |
| `trail`   | 190 / 19 | 0.69          | 4.5 %     | 221 ms       | 492 ms          | stretchy highlight, the edge that lags       |
| `pop`     | 520 / 16 | 0.35          | 30.2 %    | 88 ms        | 621 ms          | icon, chip or number popping on select       |
| `fade`    | 420 / 32 | 0.78          | 1.3 %     | 179 ms       | 333 ms          | opacity and small slides                     |
| `stagger` | 45 ms    |               |           |              |                 | between items entering one after another     |

Read this as: they reach the target as fast as our default durations (130 to 220 ms against our 150 to 250 ms) and spend the remaining 200 to 400 ms on a small, mostly invisible settle. Three things make it feel alive, and none of them is the overshoot alone:

1. **Velocity carries over.** Retargeting mid-flight keeps the current velocity, so a second click or a new hover bends the motion instead of restarting it. Our CSS transitions restart from zero velocity.
2. **One property, several springs.** Width and height, or a highlight's two edges, get different stiffness, so shapes land sideways first and then drop, or stretch on the way and gather on arrival.
3. **Velocity drives secondary motion.** Squash, stretch, tilt and blur are computed from a spring's current speed, not keyframed.

## How Fabricator differs today

- `registry/fabricator/motion.ts` defines roles (`feedback`, `move`, `popup`, `bounce`, `settle`, …) as durations plus cubic-bezier curves, in four speeds (`smooth`, `default`, `snappy`, `instant`), with `data-motion` and `--motion-scale` on top. Springs exist only as `linear()` curves sampled from a bounce amount (`getSpringSamples`), so they cannot be interrupted with velocity.
- Registry components animate in CSS; no item depends on `motion`. JS motion is in-house where needed: `lib/fluid-hover.tsx` (highlight glides on a CSS transition of transform, width and height), `lib/image-compare-model.ts` (its own stiffness/damping integrator, 620 / 44), `lib/bot-face-motion.ts`, `lib/avatar-group-parting.tsx`.
- Native (`registry/native/lib/motion.ts`) reads the same `MOTION_SPEEDS` and samples the same spring curves for Reanimated.
- Already close to the reference: switch thumb stretching on hover, rating star pop on `motion-bounce`, slider fill glide, accordion bounce, avatar group parting, tooltips skipping their entrance once one is open.

## Recommendation

**Pick: add a spring layer to the motion tokens and a small shared spring model, then upgrade the interactive core components first.** The reference's feel comes from interruptible springs with velocity and split-edge springs; CSS durations cannot express either, and the in-house integrator already exists in `image-compare-model.ts`.

- Alternative: adopt the `motion` package in registry items. Rejected for now: every item installs a new runtime dependency into user projects, and the repo's pattern is in-house JS motion with CSS fallbacks.
- Alternative: only retune durations and `linear()` curves. Rejected: it gets the overshoot but not the velocity carry-over, split edges or squash, which is most of what the user liked.

## Phases

### Phase 0: spring foundations

1. **Spring tokens in `motion.ts`.** Add a `springs` record per speed with the reference's names and numbers (`follow`, `settle`, `soft`, `lead`, `trail`, `pop`, `fade`) plus `stagger`. Speeds keep the damping ratio and scale time: `smooth` divides stiffness by 1.69 (×1.3 time), `snappy` multiplies by 1.78 (×0.75), `instant` sets no spring (jump to target). `--motion-scale` scales time the same way (stiffness ÷ scale², damping ÷ scale). `data-motion="off"` and Reduce Motion: critical damping, as the reference does, so values still arrive but never overshoot; `off` jumps.
2. **Shared spring model**: `registry/fabricator/shared/lib/spring-model.ts`, pure and tested (`spring-model.test.ts`): `createSpring`, `stepSpring` (semi-implicit Euler, 4 substeps, dt capped at 1/30 s), `isSpringAtRest`, `retargetSpring` keeping velocity, `toSpringEasing(k, c)` for CSS `linear()` when a spring only enters or leaves, and the duration until rest so CSS and JS paths agree. Move `image-compare-model.ts` onto it.
3. **One rAF adapter**: `lib/spring-loop.ts` runs every active spring in one frame loop, stops when all are at rest, and pauses in hidden tabs. Components write transforms through refs, never React state per frame.
4. **Native**: `native/lib/motion.ts` maps the same tokens to Reanimated `withSpring({ stiffness, damping, mass: 1 })`, so both platforms use one set of numbers (contract 9).
5. **Docs**: `docs/STYLES.md` motion section and the motion docs page gain the spring table; `skills/fabricator/foundations.md` tells agents which preset to use for what.
6. Tests: preset overshoot and settle times (the table above, ±10 ms), speed scaling keeps the damping ratio, reduced motion has zero overshoot, retarget keeps velocity, loop stops at rest.

## Scenarios every phase covers

- **Interruption**: retargeting mid-flight keeps velocity; rapid clicks never queue animations; closing while opening reverses from the current value.
- **Reduce Motion and `data-motion`**: springs go critically damped (no overshoot), squash, tilt and blur are dropped, staggers collapse to 0; `instant` and `off` jump. Autoplay never runs in components.
- **Keyboard**: arrow keys move highlights with the same springs; focus rings never animate; keyboard-triggered changes in toolbars may skip motion as in Kokonut's toolbar.
- **Touch**: drag paths use pointer capture and release it on leave; flick velocity measured over the last stretch only; horizontal swipe vs vertical scroll decided after a small threshold.
- **RTL**: leading edge picked by visual direction, not index.
- **Layout changes mid-animation**: measure with `ResizeObserver`; springs retarget, never snap, except on first measure.
- **SSR and hydration**: first render is the rest state; no measurement-dependent markup.
- **Performance**: one shared loop, transforms and opacity only, stops at rest, no per-frame React renders; goo filters and backdrop blur capped (see memory on backdrop-filter layers).
- **Speeds**: every component checked at `smooth`, `default`, `snappy` and `instant`.
- **Native parity**: same tokens through Reanimated; gesture-heavy pieces may land native-first (pull to refresh, swipe deck).

## Verification per component

Each Phase 1 and 2 item is cloned motion-faithful against its reference with the reanimate workflow: capture the reference card and our docs preview with the same trigger, compare per frame, pass when timing is within ±80 ms, the easing family and overshoot match, and the stagger order matches. Light and dark, keyboard only, phone and desktop widths, axe clean, as in `AGENTS.md`.

## Risks and open decisions

- **Licence**: DesignBookmark's 57 non-MIT components are reimplemented from behaviour and numbers only. Kokonut UI and SmoothUI code is MIT; any adapted file is credited in `NOTICE.md`.
- **Spring vs duration roles**: keep both. Durations stay for enter and exit of overlays (predictable, CSS-only); springs drive anything interruptible or pointer-driven. Decide per component in Phase 1, default to the role table.
- **Bundle**: the spring model and loop must stay small; measure the gzip size in Phase 0 and state it in the changelog.
- **Goo filters**: SVG blur thresholds are expensive on large areas and render differently in Safari; keep them out of core components.
- **Text Motion** is being built in this tree by another session; P4 and P12 changes go through that plan (`docs/plans/text-motion.md`), not around it.
