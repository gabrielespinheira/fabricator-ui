# Opt-in React package distribution

**Status** Implemented locally for the Base UI preview. Publishing and fresh package-manager qualification are release gates.

## Product contract

Ship `@fabricator-ui/react` as a second distribution of the existing React web registry. Keep copy-in as the default for `fabricator-ui init`, `create`, and Get started. Package users install one direct Fabricator dependency, import components by name, and update the package through their package manager. Both distributions use the same component source, styles, and token contract.

```sh
# Existing React web project
npx fabricator-ui@latest init --distribution package --yes

# New React web monorepo
npx fabricator-ui@latest create my-app --distribution package --yes

# Manual setup in an existing app
bun add @fabricator-ui/react
```

```tsx
// At the application entry or root layout
import "@fabricator-ui/react/styles.css"

// In a component file
import { Button } from "@fabricator-ui/react/button"
```

- **Pilot.** Package Base UI Button, Input and Dialog. Include their full runtime, CSS and type closure. Use them to qualify exports, dependency isolation, theming and keyboard behavior before expanding the catalog.
- **Public preview.** Start with Base UI and Fabricator Icons. Qualify Button, Input, Dialog, Textarea, Label, Card, Badge, Checkbox, Switch, Select, Dropdown Menu and Tabs. Publish the exact supported catalog with the release. Keep App Shell starters, blocks, alternate primitive bases, large component families and non-web renderers on their existing copy-in paths. Expand package coverage against measured install and CSS costs.
- **Automated setup.** Qualify existing Next.js App Router and Vite React apps and new Next.js and Vite web-only monorepos first. A supported web workspace in a mixed existing repo can opt in explicitly with `--cwd`. Grow the wizard to offer new mixed and desktop scaffolds after their end-to-end checks pass. Package support in a desktop host follows its web renderer.
- **Dependency ownership.** React and React DOM are host peers, starting with the React 19 range qualified by fixtures. Fabricator owns tested pins for implementation dependencies. The consumer lockfile still records transitive dependencies, and incompatible requirements elsewhere can produce multiple versions. A monorepo can own one Fabricator version in a private `packages/ui` wrapper and re-export the components and shared theme to its apps. To upgrade a pinned install, change the version in the owning workspace, for example with `bun add @fabricator-ui/react@<version>` from that workspace. [npm peer dependencies](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#peerdependencies)

## Local verification

The packed preview exports 12 components and its styles. The tarball measured 35.8 kB. The compiled stylesheet was 16.9 kB gzip in the Vite Button-only fixture. The Button-only production builds excluded Dialog and its icon dependencies.

Next.js App Router and Vite built from the packed artifact with the checkout's installed dependencies. Two Vite apps built through one private `packages/ui` wrapper holding the package. These fixtures verify the artifact and import paths. Fresh package-manager resolution and the deployment sequence remain separate release checks.

In the Vite fixture, host Tailwind utilities overrode the package styles with either import order after the package preserved the CSS layer declaration through optimization.
