# Retire the SwiftUI and Kotlin Compose previews

**Status** Implemented locally. The registry, CLI, demos, and CI have four parity targets. The earlier audit at `55bd03ce` found 262 removable tracked files and 23,044 source lines. The cleanup keeps the historical verification records and removes 211 tracked files.

The full registry build passed. The 1,890 retained registry files match the baseline after removing the retired metadata and accounting for one comment update. Strict React Native parity and upstream parity passed. All 806 React explorer routes passed, and the Tauri frontend builds from the same catalog. The production site served the supported registry and setup routes and returned 404 for the retired routes. Electron loaded the production desktop page and exposed its native bridge.

Release verification remains open. Workspace-wide checks reported failures in concurrent setup and block work. Tauri's offline host check requires `tauri` 2.12.7 in the Cargo cache. Device builds and the dependency-installing CLI end-to-end suite have yet to run.

## 5. Publish the retirement

- Default to retiring new installs and updates for the two preview renderers at the next release. Installed copy-in projects own their source files and can keep building them. The last source release is the recovery point. An older CLI still calls the hosted registry, so pinning the CLI alone cannot recover retired payloads.
- Remove the SwiftUI/Compose rewrite in `apps/web/next.config.mjs` for the default rollout. Verify that both the public `/r/fabricator/{swiftui,compose}/` URLs and the direct `/r/{swiftui,compose}/` URLs stop serving previews, and that the React Native route still returns its original payload. If an existing consumer needs install access, verify a frozen snapshot at the old URLs with the last preview CLI before the site cutover. Keep that snapshot out of the active source and build pipeline.
- Publish the CLI and registry changes through the existing release workflow after the checks below pass. Record the pre-cutover site deployment and source revision. If a supported registry, CLI, or demo regresses, restore the last good site deployment or revert the removal as appropriate. If npm has already published the CLI, issue a corrective release.
