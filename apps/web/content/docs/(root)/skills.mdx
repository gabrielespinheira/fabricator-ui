The Fabricator skill teaches your AI assistant to design and build product interfaces with Fabricator UI. With it installed, the assistant reads your project, works out what the screen is for, picks the components that fit, designs the errors and edge cases with the happy path, and writes code that follows the library's rules for your base, icon library and platforms.

For example, you can ask:

- _"Build the Members page: invites, roles, seats and what happens when they run out."_
- _"Design a New campaign flow that doesn't feel like a form."_
- _"Create an overview for on-call engineers, for web and the phone app."_
- _"This settings page is a wall of fields. Rework it."_
- _"Make a chat view that streams the assistant's replies."_
- _"Switch this project to preset a2r6bw."_
- _"Update the button component but keep my changes."_

The skill is published on [skills.sh](https://skills.sh/gabrielespinheira/fabricator-ui/fabricator), the open directory of agent skills.

## Installation

The CLI can do it for you, for as many assistants as you use. It writes the skill into your project and configures the [MCP server](/docs/mcp):

```bash
npx fabricator-ui@latest agents add claude codex
```

Or install it with the `skills` CLI:

<Steps>

### Set up Fabricator UI

The skill works in projects whose `components.json` lists the `@fabricator` registry. If yours doesn't yet, run `init`. See [Installation](/docs/installation).

```bash
npx fabricator-ui@latest init
```

### Install the skill

Run the following command in the root of your project:

```bash
npx skills add gabrielespinheira/fabricator-ui
```

The CLI asks which agents to install the skill for, then copies it into each agent's skills folder (for Claude Code, `.claude/skills/fabricator`). It also writes a `skills-lock.json` that records the source and version. Commit both so everyone on the project gets the skill.

### Start your assistant

Restart your assistant, or start a new session, and ask for something you want to build. The skill loads on its own when the task involves Fabricator UI.

</Steps>

### Installation options

Install for a specific agent and skip the prompts:

```bash
npx skills add gabrielespinheira/fabricator-ui --skill fabricator --agent claude-code --yes
```

Install for every agent the CLI supports:

```bash
npx skills add gabrielespinheira/fabricator-ui --agent '*'
```

Install once for your user account, so the skill is available in every project:

```bash
npx skills add gabrielespinheira/fabricator-ui --global
```

### Manual installation

The skill is a folder of Markdown files. To install it without the skills CLI, copy [`skills/fabricator`](https://github.com/gabrielespinheira/fabricator-ui/tree/main/skills/fabricator) from the repository into your agent's skills folder, for example `.claude/skills/fabricator` for Claude Code.

## Usage

You don't call the skill by name. Its description tells the assistant when to load it: when you ask to design, build or improve a screen with Fabricator UI, choose or compose its components, set it up or update it, or when the project's `components.json` lists `@fabricator`. Ask for what you want in plain language.

When the skill loads, the assistant follows the same process, scaled to the task:

1. **Read the ground.** Your agent instructions, `DESIGN.md`, `components.json`, installed components and a neighbouring screen: the base, the theme, the icon library and every platform the product ships on.
2. **Write the brief.** Who is on the screen and what they came to do, the objects and actions, every value the feature needs, and which of those it can know, infer or default instead of asking.
3. **Shape the screen** from a pattern, a recipe or a block.
4. **Choose components** from the catalogue, installed ones first, and read their docs for your base.
5. **Design the flows and states:** loading, empty, partial, stale, denied, over the limit, failed, undone.
6. **Fit every platform:** phone, tablet, desktop browser, desktop window, React Native.
7. **Build** with the API rules for your base.
8. **Look, then fix.** It opens the running screen at phone, tablet and desktop widths in both themes, uses the keyboard, forces the failure states, and repeats until a pass finds nothing.

It runs `fabricator-ui` commands only when the task needs them, through the runner that matches your lockfile, and never overwrites a component without your approval.

### Updating components

Ask the assistant to update a component and keep your changes. It previews the update with `add --dry-run` and `--diff`, overwrites the files you haven't touched, and merges registry changes into the ones you have. It only runs `--overwrite` after you approve it.

### Switching presets

Ask the assistant to switch presets. It asks how you want to apply the preset (overwrite, partial, merge or skip) and then runs the matching `apply` or `init --preset` command. See [CLI](/docs/cli#apply).

## What the skill knows

| Area        | What the assistant learns                                                                                                  |
| ----------- | -------------------------------------------------------------------------------------------------------------------------- |
| Patterns    | Page anatomy, hierarchy, the grid, dashboards, and blueprints for billing, members, integrations, approvals and more       |
| Asking      | How to collect what a feature needs without a form: a ladder from known to typed, draft-first setup, the control per value |
| Components  | Every component, when to reach for it, what is easy to miss, and which neighbour to pick instead                           |
| States      | What each region and action does when it loads, fails, conflicts, hits a limit or is denied, and how loud to be about it   |
| Platforms   | What each part of a screen becomes on phones, tablets, desktop browsers, desktop windows and React Native                  |
| Foundations | Surfaces, colour roles, type, space, density, shape, motion and the small details that make a screen look finished         |
| Recipes     | Working layout code for dashboards, lists, setup pages, settings, create overlays and states                               |
| Rules       | Composition, fields, styling, icons, loading, chat, the differences between bases, React Native, SwiftUI and Compose       |
| Setup       | The CLI, presets, registries, theming and the [MCP server](/docs/mcp)                                                      |

Each area is a separate file. The assistant reads one only when the task touches it, so the skill adds little to the context of each session.

## Skill and MCP server

The skill and the [MCP server](/docs/mcp) work well together:

- The **skill** carries knowledge: the design process, the component catalogue, the rules and the CLI reference. It is plain text in your project and needs no running process.
- The **MCP server** gives the assistant tools to list, search, view and install items from every registry in your `components.json`.

With the skill alone, the assistant uses the CLI for the same tasks. Add the MCP server if your assistant works better with tools than with shell commands, or if you browse many registries.

## Keeping it up to date

Update the skill to the latest version:

```bash
npx skills update fabricator
```

List the skills installed in your project:

```bash
npx skills list
```

Remove the skill:

```bash
npx skills remove fabricator
```

## Troubleshooting

### The assistant doesn't use the skill

1. **Check that it's installed.** Run `npx skills list` and look for `fabricator` under your agent.
2. **Start a new session.** Most assistants read skills when a session starts.
3. **Check the project.** Run `npx fabricator-ui@latest doctor`. The skill looks for `@fabricator` in your `components.json`.
4. **Name the library.** Mentioning "Fabricator UI" or `@fabricator` in your request makes the assistant load the skill.

### The assistant writes code for the wrong base or icon library

The skill reads both from your project's files and, when they leave it unclear, from `npx fabricator-ui@latest info --json`. Run it yourself and check `config.base` and `config.iconLibrary`. If they are wrong, fix them in `components.json`.
