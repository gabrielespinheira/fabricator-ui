## Types

`Input` is for text: `text`, `email`, `tel`, `url`, and `password` and
`search` below. It never shows the browser's own controls, so every field
looks and moves like the rest of the library in light and dark. Every other
input type has a component of its own, built on the same frame. The preview at the top of this page shows each one:

| Type                          | Use                                                                                                                                                |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`, `email`, `tel`, `url` | `Input`                                                                                                                                            |
| `password`                    | `Input` in an [Input Group](/docs/components/base/input-group) with a show button ([Password](#password))                                          |
| `search`                      | An [Input Group](/docs/components/base/input-group) with a clear button ([Search](#search)), or [Search](/docs/components/base/search) in toolbars |
| `number`                      | [Number Field](/docs/components/base/number-field)                                                                                                 |
| `date`                        | [Date Picker](/docs/components/base/date-picker)                                                                                                   |
| `time`                        | [Time Input](/docs/components/base/time-input)                                                                                                     |
| `datetime-local`              | [Date Picker](/docs/components/base/date-picker) and [Time Input](/docs/components/base/time-input) side by side                                   |
| `month`                       | [Month Input](/docs/components/base/month-input)                                                                                                   |
| `color`                       | [Color Picker](/docs/components/base/color-picker)                                                                                                 |
| `file`                        | [File Upload](/docs/components/base/file-upload)                                                                                                   |
| `range`                       | [Slider](/docs/components/base/slider)                                                                                                             |
| `checkbox`, `radio`           | [Checkbox](/docs/components/base/checkbox), [Radio Group](/docs/components/base/radio-group)                                                       |

or any parent, and the input stays the same height as the buttons beside it.

## API Reference

### Input

`Input` takes every prop of the native `input` element and passes it through.

| Prop           | Type      | Default  | Description                                                         |
| -------------- | --------- | -------- | ------------------------------------------------------------------- |
| `type`         | `string`  | `"text"` | A text type: `text`, `email`, `password`, `tel`, `url` or `search`. |
| `aria-invalid` | `boolean` | -        | Turns the frame red. Pair with `data-invalid` on the `Field`.       |
| `disabled`     | `boolean` | `false`  | Dims the input and blocks interaction.                              |
| `className`    | `string`  | -        | Merged last, for layout such as width.                              |

## Accessibility

- Give every input a visible label with `FieldLabel` and `htmlFor`, or an
  `aria-label` when the label is implied (a search field with an icon).
- Describe errors with `FieldError` inside a `Field` that has `data-invalid`,
  and set `aria-invalid` on the input so assistive technology announces it.
- Focus shows a firmer neutral ring; the caret marks the focused field.
- Text is 16px below the `md` breakpoint so iOS doesn't zoom into the field.
