Click the field or press an arrow key and the list opens under it while you keep typing: the arrows move through the times, and typing jumps to the nearest one. The text is read on Enter or when the field loses focus, then rewritten in the display format, so `930`, `9:30 am` and `09:30` all land on the same value: `"09:30"`, the 24-hour string a time field submits. Time Range Input pairs a start and an end: the end's list counts the duration from the start, and moving the start keeps it.

Time Input is part of the Fabricator style. It's composed from [Input Group](/docs/components/base/input-group) and [Popover](/docs/components/base/popover), so the frame, focus ring and invalid state match every other field, and its list moves like a menu: one highlight glides between times and the chosen one sits on the sliding selection. It never shows the browser's own time picker.

## Usage

```tsx
import { TimeInput, TimeRangeInput } from "@/components/ui/time-input"
```

```tsx
<TimeInput aria-label="Start time" />
<TimeRangeInput defaultValue={{ start: "11:00", end: "12:45" }} />
```

## Composition

```text
TimeInput
├── InputGroup
│   ├── InputGroupAddon          the clock; a click opens the list
│   └── InputGroupInput          a combobox: the text, and every input prop
├── PopoverContent               anchored to the whole field
│   └── listbox                  the times, every `step` minutes
└── input[type=hidden]           with `name`: the time as HH:mm

TimeRangeInput
├── TimeInput                    the start
├── arrow
├── TimeInput                    the end, with `startTime`: its list shows durations
└── duration                     once both are set
```

`className` goes on the root, for layout. Every other prop goes to the text input: `id`, `placeholder`, `disabled`, `required`, `aria-*`, `onBlur` and `onKeyDown` among them.

## Examples

### Field

Put it in a `Field` with a `FieldLabel` pointing at its `id`, and a `FieldDescription` for what people can type.

<ComponentPreview styleName="base-nova" name="time-input-field" />

### 24-hour

Without `hourCycle`, the field follows the reader's locale: `6:45 PM` in the US, `18:45` in most of Europe. It renders 12-hour on the server and switches right after hydration. `hourCycle={24}` or `hourCycle={12}` fixes the clock. Typing reads both either way, and the value is `"18:45"` in both.

<ComponentPreview styleName="base-nova" name="time-input-24-hour" />

### Steps and range

`step` sets the minutes between listed times, 15 by default. `minTime` and `maxTime` keep the list within them, and a typed time outside them is rewritten, marked invalid, and leaves the value empty.

<ComponentPreview styleName="base-nova" name="time-input-range" />

### Start and end

`TimeRangeInput` takes `{ start, end }`. The end's list starts one step after the start and shows each time's duration, and the total sits beside the fields. Moving the start moves the end with it, so the duration holds. A typed end at or before the start is marked invalid.

<ComponentPreview styleName="base-nova" name="time-input-duration" />

For only the duration list, give a single `TimeInput` a `startTime`.

### Controlled

Control the value with `value` and `onValueChange`. It changes when the text is committed or a time is picked, not on every keystroke.

<ComponentPreview styleName="base-nova" name="time-input-controlled" />

### Date and time

For a date and a time, put a [Date Picker](/docs/components/base/date-picker) and a Time Input side by side. Each keeps its own value, and with `name` each submits its own field.

<ComponentPreview styleName="base-nova" name="time-input-date-time" />

## What it reads

| Typed                                     | Becomes                                 |
| ----------------------------------------- | --------------------------------------- |
| An hour (`9`, `21`)                       | That hour, on the hour                  |
| Hours and minutes (`9:30`, `9.30`, `930`) | That time                               |
| A meridiem (`9pm`, `9:30 p.m.`, `12am`)   | That time in 24-hour form               |
| `noon`, `midnight`                        | `12:00`, `00:00`                        |
| Nothing                                   | No value                                |
| Anything else, or a time that can't be    | No value; the text stays and is invalid |

The rules are pure functions in `lib/time-input-model.ts` (`parseTimeText`, `commitTimeText`, `formatTimeValue`, `getTimeOptions`, `isTimeInRange`, `getTimeDuration`, `formatTimeDuration`, `shiftEndTime`), which you can use for your own validation.

## API Reference

### TimeInput

| Prop            | Type                                   | Default         |
| --------------- | -------------------------------------- | --------------- |
| `value`         | `string \| undefined` (`HH:mm`)        | -               |
| `defaultValue`  | `string` (`HH:mm`)                     | -               |
| `onValueChange` | `(value: string \| undefined) => void` | -               |
| `hourCycle`     | `12 \| 24`                             | the locale's    |
| `step`          | `number` (minutes)                     | `15`            |
| `minTime`       | `string` (`HH:mm`)                     | -               |
| `maxTime`       | `string` (`HH:mm`)                     | -               |
| `startTime`     | `string` (`HH:mm`)                     | -               |
| `name`          | `string`                               | -               |
| `listLabel`     | `string`                               | `"Choose time"` |
| `placeholder`   | `string`                               | -               |
| `disabled`      | `boolean`                              | `false`         |
| `aria-invalid`  | `boolean`                              | -               |

`startTime` makes it an end time: the list starts one step after it and shows durations, and a typed time must come after it.

## Accessibility

- The field follows the WAI-ARIA combobox pattern: `role="combobox"` with `aria-expanded`, `aria-controls` and `aria-activedescendant`. Focus stays in the field the whole time, so typing and the list work together. Label it with a `FieldLabel` or `aria-label`, and describe what people can type with `aria-describedby`.
- Arrow Up and Arrow Down open the list, then move by one time and write it into the field; Page Up and Page Down move by five. Typing moves the highlight to the nearest time. Enter commits, Escape closes the list and puts the last value back.
- The list opens on the selected time, or on the time nearest now, centred. The listbox is named by `listLabel`.
- Text that isn't a time, a time outside the range, or an end at or before its start sets `aria-invalid` on the field, so the frame turns red and screen readers announce it.
- Time Range Input is a `group`; its fields are named by `startLabel` and `endLabel`. The duration is plain text after them.
- The field is never narrower than its longest time (`12:45 PM`, or `23:45` on a 24-hour clock), so a time is never cropped; it grows past a width set on it if it has to.
- Disabled, the field leaves the tab order and the hidden input isn't submitted.
