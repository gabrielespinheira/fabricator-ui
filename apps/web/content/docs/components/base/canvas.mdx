Drag a step from the library onto the canvas, or click it to add it in the middle. Drag from a step's right edge to another step's left edge to connect them: a step only takes what the one before it gives, so the line turns red over a step that can't take it. Scroll to pan, pinch or hold ⌘ and scroll to zoom, and drag across empty space to select. Right-click a step, or focus it and press Shift F10, for its menu; press C to connect it from the keyboard and ⌘K to find a step. Every change can be undone with ⌘Z.

Canvas is part of the Fabricator style. It draws with [React Flow 13](https://reactflow.dev) and none of React Flow's look: nodes are raised cards, connections are quiet lines, and the controls, menus and dialogs are the library's own components. Canvas draws with HTML and SVG rather than a `<canvas>` element, so a node can hold any component, from a badge to a form. Undo, the clipboard, connection rules, keyboard navigation and the edge shapes come from a model with no React Flow or DOM in it, shared with React Native.

## Usage

```tsx
import { Canvas } from "@/components/ui/canvas"
```

```tsx
const nodes = [
  { id: "fetch", position: { x: 0, y: 0 }, data: { title: "Fetch orders" } },
  { id: "sum", position: { x: 280, y: 0 }, data: { title: "Total by day" } },
]
const edges = [{ id: "fetch-sum", source: "fetch", target: "sum" }]

<Canvas defaultNodes={nodes} defaultEdges={edges} className="h-[480px]" />
```

Give the canvas a height: it fills its box, and takes 384px when the box has none. Nodes and edges have React Flow's shape, so data written for React Flow drops in. A node without a `type` is the default node: its `title` (or `label`), an optional `description` and `icon`, a connection point on each side.

## Saving changes

Hold the graph yourself with `useCanvasState`, or any state, and apply each change list with `applyCanvasNodeChanges` and `applyCanvasEdgeChanges`:

```tsx
const { nodes, edges, onNodesChange, onEdgesChange } = useCanvasState(
  initialNodes,
  initialEdges
)

<Canvas
  nodes={nodes}
  edges={edges}
  onNodesChange={onNodesChange}
  onEdgesChange={onEdgesChange}
  onConnect={(connection) => saveConnection(connection)}
  onDelete={({ nodes, edges }) => deleteOnServer(nodes, edges)}
  onViewportChangeEnd={saveView}
/>
```

`onConnect` and `onDelete` may return a promise. The change shows at once and waits faded until it settles; a rejection puts it back and raises a toast with Retry, and the undo history only records changes that landed.

## Your own nodes

A node component receives the node's `data`, `selected`, `status` and `invalid`, and draws itself from the node parts:

```tsx
function PromptNode({ data }: CanvasNodeProps<{ title: string }>) {
  return (
    <CanvasNode>
      <CanvasNodeHeader>
        <CanvasNodeIcon>
          <SparklesIcon />
        </CanvasNodeIcon>
        <CanvasNodeTitle>{data.title}</CanvasNodeTitle>
        <CanvasNodeStatus />
      </CanvasNodeHeader>
      <CanvasNodeContent>…</CanvasNodeContent>
      <CanvasNodeFooter />
      <CanvasHandle kind="target" side="left" accepts={["text"]} />
      <CanvasHandle kind="source" side="right" produces="text" />
    </CanvasNode>
  )
}

const nodeTypes = { prompt: PromptNode }

<Canvas nodeTypes={nodeTypes} defaultNodes={nodes} />
```

Define `nodeTypes` outside the component, so it keeps one identity. A handle's `produces` and `accepts` are value types: a connection lands only where they match, and the line turns red over a handle that can't take it. `max` caps how many connections a handle takes. Add `validateConnection` for a rule of your own; return a string and it's the reason shown.

Set `status` on a node (`running`, `success`, `warning`, `error`, `skipped`) to show a run, `color` for its icon tile, and `invalid` for a problem the footer reads out. Notes (`type: "note"`), groups (`type: "group"`) and placeholders (`type: "placeholder"`) are built in.

## Modes

`mode="edit"` (the default) changes the graph. `mode="view"` pans, zooms and selects, and the page scrolls past it until it's clicked. `mode="static"` is a picture: no controls, no edits, refitted whenever its box changes size. `panOn="drag"` pans by dragging empty space, for people used to maps; the default, `scroll`, pans like a design tool.

## Automatic layout

Canvas Layout arranges a graph in layers with [dagre](https://github.com/dagrejs/dagre). Pass it as `layout` to offer Tidy up in the canvas's menu, or call it yourself:

```tsx
import { layoutWithDagre } from "@/lib/canvas-layout-dagre"

;<Canvas layout={layoutWithDagre} />

// or, inside the canvas
const canvas = useCanvas()
canvas.layout(layoutWithDagre, { direction: "down" })
```

Any engine with the same signature works, such as ELK on a server.

## Coming from React Flow

`nodes`, `edges`, `onNodesChange`, `onEdgesChange`, `onConnect`, `fitView`, `minZoom`, `maxZoom` and `viewport` keep React Flow's names and shapes. The changes Canvas reports are plain objects rather than React Flow 13's changeset class. `reactFlow` passes any other prop to React Flow as it is (web only), and `edgeTypes` takes React Flow edge components. React Flow's attribution is hidden; Canvas credits it here and in the library's notices.

## Keyboard shortcuts

The canvas takes these while focus is inside it, never while typing in a field.

| Keys                | Action                                              |
| ------------------- | --------------------------------------------------- |
| Arrows              | Focus the nearest node in that direction            |
| Alt + arrows        | Move the selection a grid step; Shift for ten       |
| Enter               | Open the focused node                               |
| Space               | Select or deselect the focused node                 |
| C                   | Connect the focused node: pick a target from a list |
| Shift F10, Menu key | The focused node's menu                             |
| Delete, Backspace   | Delete the selection                                |
| ⌘A, ⌘C, ⌘X, ⌘V, ⌘D  | Select all, copy, cut, paste, duplicate             |
| ⌘Z, ⇧⌘Z             | Undo, redo                                          |
| ⌘G, ⇧⌘G             | Group, ungroup                                      |
| ⌘0, ⌘+, ⌘−, ⇧1      | 100%, zoom in, zoom out, fit                        |
| ⌘K, /               | Find a node                                         |
| Escape              | Clear the selection                                 |

## Accessibility

- The canvas is a labelled region with a summary screen readers read: its name, how many nodes and connections, how many are selected.
- Each node is a group named by its title and described by its connections ("In from Classify. Out to Send email."), its run state and its problem.
- Every pointer action has a keyboard path, including connecting, which picks from a list of the targets that can take the connection.
- Connections, deletions, undo and redo are announced in a polite live region.
- `CanvasOutline` is the graph as a list, for screen readers and small screens.
- Run states pair their colour with an icon; edges meet 3:1 against the page in light and dark.

## Performance

- Define `nodeTypes`, callbacks you pass and option objects once: a new identity remounts nodes.
- A node reads only its own state, so a status change re-renders one node and a drag doesn't re-render the rest.
- Past 300 nodes, offscreen nodes aren't drawn. Below half zoom nodes drop their content, and below a quarter the grid fades out.
- Undo stores what each change touched, never a copy of the graph.
