Type a date, or open the calendar with the button or Alt+ArrowDown and pick one. The text is read when the field loses focus or on Enter, then rewritten in the display format, so `2026-11-12`, `Nov 12, 2026` and `tomorrow` all land on the same kind of value: a `Date`.

The `DatePicker` field is part of the Fabricator style. It's composed from [Input Group](/docs/components/radix/input-group), [Popover](/docs/components/radix/popover) and [Calendar](/docs/components/radix/calendar), so the frame, focus ring and invalid state match every other field.

## Composition

```text
DatePicker
├── InputGroup
│   ├── InputGroupInput          the text, and every input prop
│   └── InputGroupAddon
│       └── InputGroupButton     opens the calendar
├── PopoverContent
│   └── Calendar                 one month, single selection
└── input[type=hidden]           with `name`: the day as yyyy-MM-dd
```

`className` goes on the root, for layout. Every other prop goes to the text input: `id`, `placeholder`, `disabled`, `required`, `aria-*`, `onBlur` and `onKeyDown` among them.

### Format

`format` is a [date-fns pattern](https://date-fns.org/docs/format) for the text, `MMM d, yyyy` by default. Typing reads the same pattern, and ISO `yyyy-MM-dd` always works. Pass a date-fns `locale` to write and read month names in another language; it also sets the calendar's.

<ComponentPreview styleName="radix-nova" name="date-picker-format" />

### Minimum and maximum

`minDate` and `maxDate` turn off the days outside them in the calendar, and stop its navigation at their months. A typed date outside them is rewritten, marked invalid, and leaves the value empty.

### Invalid

Pass `aria-invalid` to show your own validation, with the message in a `FieldError`. Text that isn't a date sets it on its own.

## Compositions

`DatePicker` is a date in a form. For a date on a button, a range, presets or a date with a time, compose a [Calendar](/docs/components/radix/calendar) in a [Popover](/docs/components/radix/popover) yourself. There is no root component for these; each example is the whole recipe.

A date picker is built from `Popover` and `Calendar` (there is no `DatePicker` root component):

```text
Popover
├── PopoverTrigger
└── PopoverContent
    └── Calendar
```

To pick a time as well, put a [Time Input](/docs/components/radix/time-input) beside the trigger: it takes a typed time or one from its list, and a `TimeRangeInput` takes a start and an end with the duration between them. See [Date and Time](#date-and-time) and [Date and Time Range](#date-and-time-range).

See the [React DayPicker](https://react-day-picker.js.org) documentation for more information.

The Time Input follows the reader's clock: 12-hour (`6:45 PM`) or 24-hour (`18:45`), from their locale. `hourCycle={12}` or `hourCycle={24}` fixes one; the value is `"18:45"` either way.

### Date and Time Range

The days from a range calendar, and a start and an end time below them. On a single day the times are a `TimeRangeInput`: the end's list counts the duration from the start, moving the start keeps it, and an end at or before the start is marked invalid. Across days, any two times work.

## What it reads

| Typed                                 | Becomes                                 |
| ------------------------------------- | --------------------------------------- |
| The display format (`Nov 12, 2026`)   | That day                                |
| ISO (`2026-11-12`)                    | That day                                |
| `today`, `tomorrow`, `yesterday`      | That day, from the person's clock       |
| Nothing                               | No value                                |
| Anything else, or a day that can't be | No value; the text stays and is invalid |

Case and extra spaces don't matter. Years need four digits, so `Nov 12, 26` isn't read as the year 26. The rules are pure functions in `lib/date-picker-model.ts` (`parseDateText`, `commitDateText`, `formatDateValue`, `formatIsoDate`, `isDateInRange`), which you can use for your own validation.

## Accessibility

- The text input is a plain text field: label it with a `FieldLabel` or `aria-label`, and describe the format with `aria-describedby`.
- Alt+ArrowDown in the field opens the calendar (announced through `aria-keyshortcuts`). The button is named by `calendarLabel` and reports `aria-expanded`.
- The calendar opens on the selected or typed day's month, with focus on that day. Arrow keys move by day and week, Page Up and Page Down by month, Enter or Space picks, and Escape closes.
- Picking a day closes the calendar and returns focus to the field.
- Text that isn't a date, or a date outside the range, sets `aria-invalid` on the field, so the frame turns red and screen readers announce it.
- Disabled, both the field and the button leave the tab order, and the hidden input isn't submitted.
