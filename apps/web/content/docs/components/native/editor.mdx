## Installation

```bash
npx fabricator-ui@latest add editor
```

## Usage

```tsx
import {
  Editor,
  EditorBubbleMenu,
  EditorContent,
  EditorFooter,
  EditorKeyboardBar,
  EditorLinkPopover,
  EditorToolbar,
  EditorWordCount,
} from "@/components/ui/editor"
import { Markdown } from "@/components/ui/markdown"
import { Text } from "@/components/ui/text"
import { Editor, EditorContent } from "@/components/ui/editor"
```

```tsx
<Editor defaultValue={notes} className="w-full">
  <EditorToolbar />
  <EditorContent />
  <EditorBubbleMenu />
  <EditorLinkPopover />
  <EditorKeyboardBar />
  <EditorFooter>
    <EditorWordCount />
  </EditorFooter>
</Editor>
```

## API reference

Props it adds to what it wraps: `autoFocus`, `command`, `defaultValue`, `kits`, `onValueChange`, `placeholder`, `readOnly`, `scrollEnabled`, `size`, `syntax`, `value`.

## Differences from web

**New engine.** The surface is our own native text view (`@fabricator-ui/editor-native`, one `UITextView` holding the whole document), driven by the same store and rules as the website. iOS only for now: on Android the content shows the document read-only until the Android view lands, and the app needs a development build, not Expo Go. There's no selection bar on touch, so `EditorBubbleMenu` renders nothing and the keyboard bar carries the marks. There is no slash menu: formatting comes from the toolbar, the keyboard bar, Markdown shortcuts and a hardware keyboard's shortcuts. The link editor is a dialog. Tables draw as the Markdown preview's grid in the text view and edit in a sheet on phones and tablets (a tap on the table opens it): a grid of cell fields, rows and columns added and removed at the focused cell, the focused column's alignment, Cancel and Done, where the website edits them in place. Code blocks wrap their lines instead of scrolling sideways (one text view can't scroll a paragraph on its own); their language and Copy are drawn in the block's strip, and a tap on the language opens a sheet to pick another. While the editor has focus, `EditorKeyboardBar` takes the bottom of the screen from the App Shell's bottom nav (through the `bottom-bar` slot): a floating capsule in the bottom nav's place, docked full width on top of the on-screen keyboard while that's up, with Done giving the bottom nav back. It needs `KeyboardProvider` from `react-native-keyboard-controller` at the app's root.

## Accessibility

Parts set `role="group"`, `role="radio"`, `role="radiogroup"`, `role="separator"`, `role="toolbar"`, read by VoiceOver and TalkBack. Give a control with no text an `accessibilityLabel`.
