---
title: React Native differences
description: What each React Native component does differently from its web version, and why.
---

Every component has a React Native version with the same name, exports, variants, sizes and tokens. A check in the repo compares them, so this table is the complete list of differences.

Across all of them: `onPress` replaces `onClick`, `hover:` styles become `active:`, and text goes through `Text`, since React Native has no cascade. A screen written for the web won't run on native unchanged, because `<div>` and `<span>` don't exist there.

- **Same**: the same use.
- **Touch input**: the same API, with a touch gesture in place of a web input.
- **New engine**: the same API, with a DOM-only library replaced underneath.
- **Kept for imports**: exists so code compiles, and does nothing.

Interface sounds are the same on React Native, under the same `<SoundEffects />`, with a haptic for each. The ring switch silences them.

| Component | Kind | What's different |
| --- | --- | --- |
| [Accordion](/docs/components/native/accordion) | Same |  |
| [Alert](/docs/components/native/alert) | Same |  |
| [Alert Dialog](/docs/components/native/alert-dialog) | Same |  |
| [App Nav](/docs/components/native/app-nav) | Touch input | Rows reorder on a long press, so a reorderable row's menu sits on its trailing button, and on the icon rail it has none. Keyboard reordering has no equivalent. |
| [App Shell](/docs/components/native/app-shell) | Touch input | On tablets the sidebar's toggle stays in the header while the sidebar can collapse, the toggles have no tooltip, and the status bar is its row plus half the home indicator's space, with its ends the same distance inside the cards' edges. On phones the sidebar reveals behind the page, panels open as sheets with a grab handle and full-width tabs, a panel's toggle draws a bottom panel, and the nav's mobile items become a tab bar, flat or floating, on a surface of your own through `capsule` (a `GlassView` for Liquid Glass). The page scrolls under the header, which sits on a fade behind the status bar, instead of showing a hairline. The breadcrumb shows the way up, and the page's name only once its heading has scrolled away. `window`, `shortcut` and `shortcutScope` are accepted and do nothing, since React Native has no window controls or global key events. Panels don't drag to resize, and the layout is only saved if you pass `storage`. |
| [Aspect Ratio](/docs/components/native/aspect-ratio) | Same |  |
| [Attachment](/docs/components/native/attachment) | Same |  |
| [Avatar](/docs/components/native/avatar) | Same |  |
| [Badge](/docs/components/native/badge) | Same |  |
| [Breadcrumb](/docs/components/native/breadcrumb) | Same | Links are pressables: use `onPress` or `render`. |
| [Bubble](/docs/components/native/bubble) | Same |  |
| [Button](/docs/components/native/button) | Same | `onPress` replaces `onClick`. Small sizes keep a 44pt target through `hitSlop`. |
| [Button Group](/docs/components/native/button-group) | Same |  |
| [Calendar](/docs/components/native/calendar) | New engine | `react-day-picker` is DOM-only, so the grid is its own on `date-fns`, with the same props where they aren't DOM. |
| [Card](/docs/components/native/card) | Same |  |
| [Carousel](/docs/components/native/carousel) | New engine | `embla` is DOM-only. Paging is native, with the same parts and `CarouselApi`. `loop` rewinds to the first slide instead of wrapping. |
| [Checkbox](/docs/components/native/checkbox) | Same |  |
| [Collapsible](/docs/components/native/collapsible) | Same |  |
| [Combobox](/docs/components/native/combobox) | New engine | A filtered list in a dialog, in place of Base UI's combobox, with the same parts. Typing happens in the dialog rather than the trigger. |
| [Command](/docs/components/native/command) | New engine | `cmdk` is DOM-only. A filtered list, with the same parts. Results keep their written order instead of ranking by score, and no keyboard shortcut opens it. Shortcuts show from the `sm` breakpoint, since a phone has no keyboard. |
| [Context Menu](/docs/components/native/context-menu) | Touch input | A long press opens it, in place of a right click. Shortcuts show from the `sm` breakpoint, since a phone has no keyboard. |
| [Density](/docs/components/native/density) | Same | `DensityProvider` sets scoped variables, with no wrapper view. Phones default to spacious, and there a control's `size="sm"` is a step down, 36pt, and `size="lg"` a step up, 52pt, rather than compact and spacious. Tablets take their own step in place of spacious: 40pt controls with the same 15pt text, `sm` 34pt, `lg` 48pt. `FabricatorRoot` sets it from the window's width; a density picked on purpose stays. |
| [Dialog](/docs/components/native/dialog) | Same |  |
| [Direction](/docs/components/native/direction) | Kept for imports | Fabricator UI is left-to-right only, so `DirectionProvider` passes its children through. |
| [Drawer](/docs/components/native/drawer) | New engine | `vaul` is DOM-only. Gestures run on the UI thread, with swipe to dismiss and keyboard avoidance. `snapPoints` is accepted and does nothing. |
| [Dropdown Menu](/docs/components/native/dropdown-menu) | Same | `side` takes `top` and `bottom`; `left` and `right` fall back to `bottom`. Shortcuts show from the `sm` breakpoint, since a phone has no keyboard. |
| [Empty](/docs/components/native/empty) | Same |  |
| [Field](/docs/components/native/field) | Same |  |
| [Hover Card](/docs/components/native/hover-card) | Touch input | A long press opens it; a tap still goes through to the trigger. |
| [Input](/docs/components/native/input) | Same | `onChangeText` is the usual way to read a value, as with any `TextInput`. |
| [Input Group](/docs/components/native/input-group) | Same |  |
| [Input Otp](/docs/components/native/input-otp) | New engine | `input-otp` is DOM-only. A hidden `TextInput` takes the code, with one-time-code autofill. |
| [Item](/docs/components/native/item) | Same |  |
| [Kbd](/docs/components/native/kbd) | Same | Visual only. Useful on tablets with a hardware keyboard. It doesn't invert inside a tooltip. |
| [Label](/docs/components/native/label) | Same |  |
| [Marker](/docs/components/native/marker) | Same |  |
| [Menubar](/docs/components/native/menubar) | Touch input | A desktop pattern: triggers in a row that scrolls, each opening its menu. A press lights a trigger; a drag scrolls the row. Shortcuts show from the `sm` breakpoint, since a phone has no keyboard. |
| [Message](/docs/components/native/message) | Same |  |
| [Message Scroller](/docs/components/native/message-scroller) | New engine | An inverted list that sticks to the bottom. |
| [Navigation Menu](/docs/components/native/navigation-menu) | Touch input | A desktop pattern: each trigger opens its content in a popover, or a sheet on phones. A press lights a trigger; a drag scrolls the row. |
| [Pagination](/docs/components/native/pagination) | Same |  |
| [Popover](/docs/components/native/popover) | Same | `side` takes `top` and `bottom`; `left` and `right` fall back to `bottom`. |
| [Progress](/docs/components/native/progress) | Same |  |
| [Questionnaire](/docs/components/native/questionnaire) | Same | Key hints show from the `sm` breakpoint, since a phone has no keyboard. |
| [Radio Group](/docs/components/native/radio-group) | Same |  |
| [Resizable](/docs/components/native/resizable) | New engine | `react-resizable-panels` is DOM-only. A drag handle, with increment and decrement actions for screen readers. Panels don't collapse. |
| [Scroll Area](/docs/components/native/scroll-area) | Same | Touch keeps native scrolling, so `ScrollBar` renders nothing, as it does on touch devices on the web. |
| [Search](/docs/components/native/search) | Same |  |
| [Select](/docs/components/native/select) | Touch input | Opens as a sheet on phones and a popover on tablets. |
| [Separator](/docs/components/native/separator) | Same |  |
| [Sheet](/docs/components/native/sheet) | New engine | Gestures run on the UI thread, with swipe to dismiss and keyboard avoidance. It travels its full size, so the finger stays on it, where the website's moves 2.5rem and fades. |
| [Sidebar](/docs/components/native/sidebar) | Touch input | On phones it reveals behind the page, following the finger, or slides over it from an edge swipe. `SidebarRail` toggles on a tap instead of resizing. Row actions always show on phones; on tablets they wait for the current row or a trackpad's hover, and a long press reaches the rest. `persist`, `shortcut`, `peek` and `onWidthChange` are accepted and do nothing. |
| [Skeleton](/docs/components/native/skeleton) | Same |  |
| [Slider](/docs/components/native/slider) | Same |  |
| [Sonner](/docs/components/native/sonner) | New engine | Sonner is DOM-only. It shares one engine with `toast`, keeping its API. `position` is accepted and unused: toasts stay at the top. A dialog opened later covers them. |
| [Spinner](/docs/components/native/spinner) | Same |  |
| [Switch](/docs/components/native/switch) | Same | Drawn by Fabricator UI, rather than the system's switch, so it matches the website. |
| [Tab Strip](/docs/components/native/tab-strip) | Touch input | The strip scrolls sideways, and tabs reorder from their menu instead of by dragging. |
| [Table](/docs/components/native/table) | Same | Views in a horizontal scroll: React Native has no table layout, so `rowSpan` isn't supported. |
| [Tabs](/docs/components/native/tabs) | Same | In dark the selected tab's pill is a translucent step over the track, so it stands out on every surface. |
| [Textarea](/docs/components/native/textarea) | Same |  |
| [Toast](/docs/components/native/toast) | New engine | Swipe to dismiss. It shares one engine with `sonner`, and a dialog opened later covers it. |
| [Toggle](/docs/components/native/toggle) | Same |  |
| [Toggle Group](/docs/components/native/toggle-group) | Same |  |
| [Tooltip](/docs/components/native/tooltip) | Touch input | A long press shows it, and screen readers read it as the trigger's hint. |
| [User Menu](/docs/components/native/user-menu) | Same | Opens as a sheet on phones. |
| [Workspace Switcher](/docs/components/native/workspace-switcher) | Same | Opens as a sheet on phones. |
