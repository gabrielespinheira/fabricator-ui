---
title: React Native differences
description: What each React Native component does differently from its web version, and why.
---

Native components keep the web component's name, exports, variants, sizes and tokens, with the differences listed below. Components listed as not yet available have explicit, dated deferrals in the parity check.

Across all of them: `onPress` replaces `onClick`, `hover:` styles become `active:`, and text goes through `Text`, since React Native has no cascade. A screen written for the web won't run on native unchanged, because `<div>` and `<span>` don't exist there.

- **Same**: the same use.
- **Touch input**: the same API, with a touch gesture in place of a web input.
- **New engine**: the same API, with a DOM-only library replaced underneath.
- **Kept for imports**: exists so code compiles, and does nothing.

Interface sounds are the same on React Native, under the same `<SoundEffects />`, with a haptic for each. The ring switch silences them.

## Not yet available

These web components are not available for React Native yet. Each deferral has a reason and date in the parity exceptions.

- **Assistant 01** (2026-11-17): New web chat block. Chat Input and Model Picker have no native versions yet (see PLATFORMS.md), so the native port waits for them.
- **Billing 01** (2026-11-25): Web billing block. A React Native port needs a phone layout for plan comparisons and native invoice downloads.
- **Board 01** (2026-11-25): New web project block on App Shell. Kanban, Properties and Record View have native versions it can compose; its React Native port waits for a phone composition of the project list, the saved views and the ticket form. Its rules are pure modules it can reuse.
- **Bottom Nav** (2026-11-26): A phone web app's tab bar. React Native apps already get theirs from the App Shell's bottom bar (lib/bottom-bar), so there is no separate native item.
- **Calendar App 01** (2026-11-17): New web calendar block. Its React Native port composes the native Event Calendar and Date Picker, with Time Input still web-only (see PLATFORMS.md).
- **Data Table** (2026-11-12): The web Data Table draws a TanStack table as an HTML `<table>` with virtual rows, sticky pinned columns and header popovers. Native needs its own grid built on a virtual list, with a horizontal header scroller and sheets for the filters; the native Data Table example keeps showing Table until then.
- **Data Table Cells** (2026-11-12): The Data Table's typed cells ship with it; they follow it to native (see data-table).
- **Finance 01** (2026-11-17): New web dashboard block built on App Shell and the charts. Its React Native port waits for a phone layout of the KPI row, charts and tables designed for touch.
- **Forgot Password 01** (2026-11-17): New web screen block. Its React Native port follows with the other auth blocks; the steps and rules are pure modules it can reuse.
- **Hold Button** (2026-11-26): New web component. The native port holds on Pressable's long press with the fill on a Reanimated timing and the release on the settle spring; it follows in its own change, with haptics at the end of the hold.
- **Mail 01** (2026-11-17): New web email block on App Shell. Its React Native port waits for a phone composition of the thread list, the thread sheet and the compose form; the folder, filter and selection rules are pure modules it can reuse.
- **Members 01** (2026-11-25): Web members block. A React Native port needs the team list, role controls and invitation flow composed for touch.
- **Messenger 01** (2026-11-17): New web chat block. Chat Input has no native version yet (see PLATFORMS.md), so the native port waits for it.
- **Morph Island** (2026-11-26): New web component. The native port measures each state with onLayout and drives width, height and the squash with withSpring on the same morph-island-model; it follows in its own change.
- **Onboarding 01** (2026-11-25): Web onboarding block. A React Native port needs native navigation and storage to resume a draft.
- **Password Strength** (2026-11-26): New web component. The native port draws the bars as Reanimated views on the same password-strength-model; it follows in its own change.
- **Segmented Meter** (2026-11-26): New web component. The native port draws the parts as flex views with animated widths on the same segmented-meter-model; it follows in its own change.
- **Settings 01** (2026-11-25): Web settings block. A React Native port needs phone navigation for sections and a native image picker for the workspace mark.
- **Sign In 01** (2026-11-17): New web screen block. Its React Native port (providers, Field, InputGroup and the in-form error) follows in its own change; login-01 to login-05 cover native sign-in until then.
- **Sign Up 01** (2026-11-17): New web screen block. Its React Native port follows with sign-in-01's; signup-01 to signup-05 cover native sign-up until then.
- **Slide To Confirm** (2026-11-26): New web component. The native port drags the thumb with a Gesture Handler pan on the same slide-to-confirm-model and springs it with withSpring; it follows in its own change.
- **Stepper** (2026-11-26): New web component. The native port draws the same parts as views with the check path in react-native-svg; it follows in its own change.
- **Text Motion** (2026-11-26): New web component on CSS keyframes. Nested Text on React Native cannot be moved, scaled or blurred piece by piece, so the port draws each piece as its own Reanimated view in a wrapping row, on the same text-motion-model; it follows in its own change.
