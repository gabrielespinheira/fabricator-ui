A rich text Editor whose value is Markdown, a Markdown component and BotFace, an animated assistant face. React Native now has a version of every published web component, and Tab Strip turns into a tab switcher on phones.

## New components

### Editor and Markdown

`npx fabricator-ui@latest add editor` adds a rich text editor whose value is Markdown: you see formatted text, and `onValueChange` gets Markdown back. A toolbar, a formatting bar over selected text, a link popover, a word count, and on phones a bar on top of the keyboard.

- **Markdown as you type.** `# `, `- `, `1. `, `[] `, `> `, ` ``` ` and `---` start blocks; `**bold**`, `*italic*`, `~~strike~~` and `` `code` `` format inline. Each is its own undo step, so Backspace gives back what you typed.
- **Saved byte for byte.** A document saved without edits is the file you opened, and an edit rewrites only the blocks it touched, so it's safe on Markdown in a Git repository. Anything it doesn't model, HTML, footnotes and math, is kept as its source.
- **Markdown.** `npx fabricator-ui@latest add markdown` draws Markdown with the editor's document typography in three sizes: headings, nested lists, tasks, quotes, code panels, tables and links, with `components` to route links and images through your app.
- **Its own engine.** No editor or Markdown library underneath: the document model, input handling, history, commands and parser are plain TypeScript, shared with React Native.
- **Kits.** Commands, shortcuts and Markdown shortcuts come from kits; a command with `surfaces: ["toolbar"]` gets a button.

### BotFace

`npx fabricator-ui@latest add bot-face` adds an animated assistant face: fourteen silhouettes in your palette colours, with blinking and eyes that follow the pointer or a touch.

## React Native

### Chat Input and Model Picker

- **Chat Input on React Native.** The same pill that stacks once the draft wraps, or a large card, with one send slot that offers voice while the draft is empty, sends, and stops a reply. Attachments, tinted mentions, the `/` menu, options, trays and the context meter come with it. Return sends, or adds a line with `submitOn="mod-enter"`, and `sticky` rides the keyboard. File drops and pasted files stay on the web, and voice draws its own glow from `voiceLevel`.
- **Model Picker on React Native.** The effort slider takes a tap or a drag, previews each level it crosses and warms from blue to violet. The routes, the models grouped by provider and the settings come with it, in a popover or a sheet of your own.
- **Questionnaire takes the website's design on React Native.** Choices are rows with a chip at the end, the letter or number for a single choice and a square that fills for a multiple one, and a chosen row holds the active fill. `QuestionnaireHeader` and `advanceOnSelect` come too, so the questions can take a chat input's place.
- **One model for both platforms.** Chat Input's and Model Picker's rules, such as what the send slot does, when the pill stacks and where the effort thumb sits, now live in shared modules the website and React Native both import.

### Six more native components

- **Six more components on React Native.** Color Picker, File Tree, File Upload, Number Field, Time Input and Time Wheel now install in Expo projects, so every published web component has a native version. Data Table, Typography and Fabricator Root have native demos too.
- **Native File Upload.** It takes URI-based assets. Supply document picking through `FileUploadPickerProvider` or `onPick`; browse stays disabled until a picker is supplied.
- **Documented differences.** Browser-only interactions, such as dropping files and the eyedropper, list what the native version does instead.
- **Icons in the examples.** The desktop and mobile examples have an Icons page with search, outline, brand and file icons, size controls and import commands. Animated icons are on the web.
- **One explorer everywhere.** The docs now use the App Shell, with the same component groups and homepage settings as the examples, and desktop component pages show the documented variants and props.

### Tab Strip on phones and more

- **A tab switcher on phones.** A phone's width fits about one and a half tabs, so on React Native phones the Tab Strip shows only the active tab, on a raised pill with a count of open tabs at its end. Tapping it opens a sheet with every tab as a card: tap a card to switch to it, tap × to close it, or long press it for the tab's menu. The sheet also has New tab and Done, so `TabStripNew` and `TabStripOverflow` draw nothing on a phone. Tablets keep the full strip, and the API is the same, so existing code needs no changes.
- **The React Native example matches the desktop one.** Its sidebar is the same component explorer: an overview, then a row per component group that holds its components. Each component opens in a tab, and the Details panel has its install command.
- **Message Scroller opens at the start.** With `defaultScrollPosition="start"`, a React Native transcript longer than the first batch of messages it renders used to open part of the way down. It now opens on the first message, and `scrollToStart()` reaches it too.
- **The editor's native view registers when installed through a link.** `@fabricator-ui/editor-native` names its podspec for Expo, so a `file:` or `link:` install no longer fails with "native component is not registered".
- **A roomier revealed sidebar on phones.** With `mobileSidebar="reveal"` the sidebar takes the screen but a 72px strip of the page, on the web and on React Native, where it used to stop at 18rem. The page in that strip has a screen's rounded corners, continuous on iOS. `--sidebar-width-mobile` (`widthMobile` on React Native) now sets only the sheet's width.
- **Sidebar rows a little shorter on phones.** On React Native they're 40pt at a phone's density, down from 44.
- **Grouped fields keep their whole frame in focus.** On React Native an input or textarea inside an Input Group (Date Picker, Search, Combobox, Month Input) painted its own focus fill over the group's top and bottom border. The group now draws the frame and its focus alone, as on the web.
- **Fields stay above the keyboard.** On iOS, `AppShellContent` makes room for the keyboard and scrolls the focused field into view, and a tap on a button works while the keyboard is up.
- **The editor's keyboard bar floats on iOS.** With the keyboard up, the Rich Text Editor's formatting bar stays a rounded capsule a few points above iOS's floating keyboard, where it used to dock square across its top. Its buttons are pills, and a divider sets Hide keyboard apart from the commands that scroll. Android keeps the docked bar on its full-width keyboard.
- **Default is the native default density.** React Native apps start on Default, and `FabricatorRoot` sizes it for the device: a phone's 44px controls and 15px text, a tablet's 40px. Compact and Spacious are a step either side (40px and 52px on a phone, 34px and 44px on a tablet), where they used to give the website's pointer sizes, which came out too small for a finger.
- **A slimmer bottom nav on phones.** The App Shell's `AppShellBottomNav` rows are 48px on a phone, down from 56, with medium-weight labels. Under the floating and glass capsules the page now quiets toward the main column's colour, as iOS's scroll edge effect does, so page text no longer reads through the bar. The App Shell options call it Bottom nav, after the component, and list Glass, the default, first: Glass, Floating, Flat.
- **A fresher effort slider.** Model Picker's effort fill now runs from sky blue to a soft violet, in the info role's chroma at a lighter tone, where it used to darken to purple and turn magenta at the top level on React Native. The thumb is the Slider's white knob, and the level dots on a chosen fill are light. The web and React Native draw it the same.
- **Popovers keep clear of the status bar.** On React Native a popover that has no room on its side opens on the other one, and none runs under the clock, the island or the home indicator, as Dropdown Menu already did.
- **One-line placeholders in the Chat Input pill.** On iOS a long placeholder in the pill truncates on its line, where it could wrap and grow the pill to two lines.
- **Chat Input trays step back on React Native.** The goal, background tasks and queued messages behind the card each sit a step further in on their own surface, as on the web. On React Native they used to draw the same width with no fill, so each tray's edge showed through the one in front. A row's reading, such as a goal's status, now truncates past 45% of the row, on both platforms, so the title stays readable in a narrow tray.
- **A folding tray stack.** `ChatInputTrays` wraps a Chat Input's trays and folds them: only the front row shows, with the other rows peeking out behind it as up to two edges, so a long queue never grows the composer. Pressing the edges opens every row, and Show less folds them again. Tray rows are shorter too, 30px at the default density, with less padding around them. On the web and React Native.

## Updated components

### Sidebar, Workspace Switcher and Command

- **Sidebar labels centre on their icons.** Row labels are trimmed to their cap height, so they no longer sit 1px above the icon. Descenders still clear the truncation.
- **Counts line up.** Sidebar badges end-align their number, so single and double digits share a right edge, and sit on the label's baseline.
- **A better workspace search.** The Workspace Switcher's `command` variant shows each workspace's description and searches it, marks the current one with the row's check at its end (and says so to screen readers), and lists its keys along the bottom on devices with a keyboard. On React Native the rows show descriptions too.
- **Command dialogs stay put.** `CommandDialog` is anchored 20% from the top instead of centred, so it no longer jumps while results change.

### Performance

Several components now do less work when something changes, with the same look and the same API.

- **Editor.** Finding a block and placing the caret reuse indexes of the document instead of walking it each time, on the web and React Native.
- **File Tree.** Moving the pointer updates the hover highlight without rendering every file again.
- **Calendar.** Picking a day keeps the calendar and its days mounted, in Base UI and Radix.
- **App Nav.** Each list checks its icon column once, in every base and on React Native.
- **App Shell.** It measures its width on resize and when the sidebar changes, and ignores unrelated changes in the page.
- **Command on React Native.** It caches which items show and rescores only items that were added or changed, and each part redraws only when the value it shows changes. Hover updates reach only the affected rows.

Fixes came along too: Command's dividers are hidden from screen readers' option lists, and the Editor toolbar stays reachable by keyboard when all its commands are disabled. Composed refs on the web now run React 19 ref cleanup functions.

## Upgrade notes

- The native `editor` installs `@fabricator-ui/editor-native`, an iOS text view, so the app needs a development build. Android shows the document read-only for now.
- Every package now shares one version, so `@fabricator-ui/editor-native` moves from 0.1.1 to 0.7.0 with no API change.
- `fabricator-ui@0.6.0` on npm was published from this release's code; 0.7.0 is the same CLI with its version and notes in order.

## Docs and examples

### Shorter group names

The component groups now have one-word names in the docs and the desktop and mobile examples:

| Before              | Now       |
| ------------------- | --------- |
| Overlays & Menus    | Overlays  |
| Navigation & Layout | Structure |
| Data & Feedback     | Content   |
| AI & Chat           | Chat      |

Basics and Forms keep their names. Every component stays in its group, in the same order and at the same link, and saved preferences still apply.

### Simpler navigation

The docs are now one page at a time inside the App Shell, without tabs or a right panel, and the docs homepage settings no longer offer them.

The Library page is gone from the docs and the desktop and mobile examples. Browse components straight from Basics, Forms, Overlays, Structure, Content and Chat. Old Library links open the overview, and component links still open their demos. The desktop and mobile examples keep their component tabs and Details panel.

### Leaner mobile example

The mobile example app drops its Blocks page and block screens to focus on components and icons. Browse components through their groups, or open Icons. Old Blocks links open the overview.

The screen checker now visits component demos only, and asking it for the old Blocks scope fails at once with a message listing the scopes it supports.
