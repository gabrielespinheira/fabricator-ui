These changes are merged and ship in the next version.

## CLI

**Tauri mobile setup.** Add a Tauri host for iOS, iPadOS and Android to a React + Vite monorepo. Web, mobile and desktop can share the Vite renderer. React Native with Expo remains the default mobile option. [Vite installation](/docs/installation/vite#tauri-mobile).

**Package installation for web, mobile and desktop.** Get started can set up all selected apps with package imports. Electron and Tauri share the web renderer and `@fabricator-ui/react`. Expo uses `@fabricator-ui/react-native`, built from the existing native registry. Copy-in remains the default. [Compare install methods](/docs/installation/install-methods).

**Fabricator Icons in monorepos.** New monorepos using Fabricator Icons remove the unused Lucide dependency added by the scaffold. Projects that select or import Lucide keep it.

**The agent skill designs features.** The fabricator skill is rewritten around product design. It starts from what a screen is for, places every value a feature needs on a ladder from known to typed so features stop turning into long forms, and knows every component by the need it answers. New references cover error, warning, limit and permission flows, what each part of a screen becomes on phones, tablets, desktop windows and React Native, the foundations, and blueprints for common SaaS features. Recipes with working layout code cover dashboards, lists, draft-first setup pages, settings, create overlays and states. The CLI, MCP, registry and theming references move to `setup/`. Run `npx fabricator-ui@latest agents add` or `npx skills update fabricator` to get it.

**The agent skill refines what it builds.** After any visual change, or when you ask it to review a screen, the skill takes screenshots at every width and theme, hands them to a sub-agent that judges them without seeing the code, checks the findings, and shows you a list to choose from before it fixes anything. It then captures the same pictures again and compares. A page probe adds what pictures hide, such as covered controls, cut-off numbers and sideways scroll.

**The agent skill knows the App Shell.** A new reference explains how the App Shell's primitives fit together, how to design the sidebar, header, panels and routes from what a product does, and which changes break the frame without an error. A recipe has navigation as data, a layout that stays mounted, pages that bring their own header and panel, a sidebar that swaps its groups for settings, and a queue with its list and open item side by side. The page probe reports a broken structure as `shellProblems`.

**Setup pages in the design guide.** `DESIGN.md` adds the Setup pattern: a draft that saves itself, one line per decision, and checks beside a live preview, in place of a long form. It also says which settings controls stay beside their label on phones, and that React Native is only missing the Data Table and the time in Date Picker.

**Menu icons in the design guide.** The `DESIGN.md` new projects receive now asks every dropdown and context-menu action to lead with its icon, so menus scan by shape and their labels share one edge. Checkbox items and sub-menu triggers keep their icon, with the check or chevron at the end. A sub-menu of plain values goes without icons, and an action with no fitting icon takes `inset`. The fabricator skill's icon, design and dashboard rules say the same.

**Cursors in the design guide.** `DESIGN.md` now says which cursor each interaction takes, on the web and in desktop windows: a pointer only on what acts on a click, text where people type, grab and grabbing on what drags, a resize cursor on an edge, not-allowed on a disabled control that keeps its tooltip, and the arrow on everything static. A drag or resize holds its cursor on the whole window. The skill's styling rules add the classes for markup made interactive by hand.

**Design guide version.** `DESIGN.md` names the Fabricator UI release it ships with in `fabricatorVersion`, kept in step with the packages by the release check. Its `version: alpha` stays: that is the DESIGN.md format's version. The `omitted` list, which tells DESIGN.md tools that token values come from the project's look, is now one line and covers motion too.

**Short choices in the design guide.** New project guidance uses the default `TabsList` for two to four options that fit on one line, including settings and filters without panels. It uses `Select` for five or more options or when the full labels cannot fit.

**Generated project formatting.** Biome and Vite+ format generated docs before the first commit.

**SwiftUI and Kotlin Compose previews retired.** The CLI and hosted registry no longer install or update SwiftUI and Compose items. Existing apps can continue using the source they copied. The preview source is available in the `fabricator-ui@0.9.0` release.

## Components

**Search is an input again.** `InputSearch`, new in Input Group, is a search field framed like every other input: the search icon at the start and a clear button once there is text. The button and Escape clear the text and keep the focus in the field; Escape on an empty field reaches the dialog around it. It works controlled or uncontrolled and takes more addons, such as a keycap. The Data Table, Kanban, Mail, Members and Messenger toolbars use it; where the Kanban toolbar has no room, a search button opens the field. The Search component, a round button that sprang open into a pill, is removed: replace `<Search collapsible={false} label="…" />` with `<InputSearch aria-label="…" />`. On web and React Native. [Search](/docs/components/base/input#search).

**Menubar removed.** The registry no longer ships Menubar on any base or on React Native: desktop apps take their menus from the window, and pages use a Dropdown Menu. A project that installed it keeps its copy.

**Components regrouped.** Forms now holds every control for entering a value: Input, Textarea, Label, Checkbox, Radio Group, Switch, Slider and Rating join it from Basics. Alert, Toast and Empty move to Basics as feedback in place, and Typography and Text Motion move to Content. The docs sidebar, the homepage filter and the desktop and mobile explorers follow.

**Highlights stretch on springs.** The highlight that follows the pointer and the selection background in tabs, toggle groups, menus, selects, comboboxes, command, the sidebar, the file tree and every other list with Fluid Hover now move each edge on its own spring. The edge facing the move is stiff and the edge behind it soft, so they stretch toward the next item and gather as they land, and a second click mid-flight bends the motion instead of restarting it. Seven named springs join the motion tokens (`follow`, `settle`, `soft`, `lead`, `trail`, `pop`, `fade`) as `--motion-spring-<name>`, plus `--motion-stagger`; each speed retimes them with the same feel, `instant` takes the overshoot out, and Reduce Motion still jumps. On web and React Native. [Springs](/docs/foundations/motion#springs).

**Time wheels that loop, on a real drum.** Time Input's wheel is rebuilt. Each column is now a 3D drum: rows bunch up and turn away towards the top and bottom instead of tilting in place, and a row brightens exactly as it crosses the band's edge. Hours, minutes and seconds loop, so 59 runs on into 00 and 12 into 1, while AM or PM stops at its ends. Drag a column, flick it to coast and slow into a row, scroll it with a mouse wheel or trackpad, or click a row to turn to it; it settles on the `settle` spring. Rows and the band are taller, the numbers larger and centred in even columns. Arrow Up now steps to the next value, as a spinbutton should. Date Picker's time column gets the same wheel. On web and React Native; React Native draws the drum from its scroll position and colours the row once it settles. [Time Input](/docs/components/base/time-input).

**Controls that land on springs.** The switch thumb lands with a small overshoot and its knob wobbles back after a press; a checkbox pops back as you let go; a typed one-time code digit drops into its slot with a bounce; the slider glides to a click or a key and settles without a visible overshoot; the copy button in Syntax Highlight turns its check in with a bounce. Menus (dropdown, context menu and select) drop their rows in one after another as they open. A number field's value rolls up or down into place when it steps. A tooltip opening right after another travels from it, resizing to its label, instead of reappearing. Every spring has a CSS form, `duration-<name>-spring ease-<name>-spring`, and `motion-stagger` staggers any list. Reduce Motion keeps fades only. On web and React Native, except the menu cascade, number roll and tooltip travel, which are web only.

**Hold Button.** A new button that confirms only when held for its whole duration: it fills from its start edge as you hold, springs back and shakes if you let go early, and shows a check when done. For deleting, publishing or paying without a dialog in the way. Space and Enter hold it too. [Hold Button](/docs/components/base/hold-button).

**Slide to Confirm.** A new track whose thumb you slide to the end to commit: it follows the finger, gives like rubber past the ends, and the ink it leaves turns the label over as it passes. Short of the end it springs back; past it, a promise from `onConfirm` spins the thumb, then the track turns the success colour with a check. Enter confirms from the keyboard. [Slide to Confirm](/docs/components/base/slide-to-confirm).

**Stepper.** A new component for the steps of a flow: finished steps draw a check, the current one pops up, and the line to the next step fills as each is done. [Stepper](/docs/components/base/stepper).

**Morph Island.** One new pill for a live activity (a timer, an upload, a call) that morphs between states: the width lands first, the height drops into place, the island keeps its volume and gives a small squash, and the states cross-fade through a blur. Screen readers hear each change. [Morph Island](/docs/components/base/morph-island).

**Password Strength.** Four bars under a new-password field fill one after another as the password gets stronger, from red to green, with a word for how strong it is. `PasswordToggle` shows and hides the password; its eye draws a slash across itself while the text is hidden. [Password Strength](/docs/components/base/password-strength).

**Segmented Meter.** Parts of one total in a single bar with a legend, such as storage by kind. A part that changes springs to its new size and the rest slide over. [Segmented Meter](/docs/components/base/segmented-meter).

**Bottom Nav.** A tab bar for phone web apps: the current tab opens to show its name on a pill that slides between tabs, and its icon pops. React Native keeps the App Shell's bottom bar. [Bottom Nav](/docs/components/base/bottom-nav).

All seven are on the web for every base; their React Native ports follow.

**Text Motion.** A new component plays text in by character, word or line. Effects are layers that combine: `fade`, `blur`, `rise`, `fall`, `slide`, `scale`, `flip` and `mask`, plus `scramble`, which settles random glyphs into the text, and `type`, which types it behind a caret. `shimmer` and `wave` loops keep a status or a word moving once it lands. `TextMotionGroup` plays a heading and its paragraph in order on one trigger, and `TextMotionRotate` cycles a word in place at the widest word's width. Every time comes from the reveal motion role, so the project's speed retimes it, `instant` and `off` show the text at once, and Reduce Motion keeps only the fades. Screen readers hear the text once, whole. `DESIGN.md` and the fabricator skill say when a website's words play in and when text stays in place. On the web; React Native follows. [Text Motion](/docs/components/base/text-motion).

**Folder.** A new component shows a folder as a tile, the way a drive does: up to three files peek out of it as blank sheets or your own thumbnails, a cover on the front holds badges and avatars, and the name and details sit below. Hover or focus lifts the files out one after another and tips the front panel open; they drop back on a quicker timing. Any palette colour or role, drawn from your surfaces with a tint of that colour so folders sit in the page, solid or frosted glass, three sizes, and `open` for a drop target. A link in the title makes the whole tile the target. On web and React Native. [Folder](/docs/components/base/folder).

**Data Table columns move.** Drag a column by its head to a new place: a copy of the head follows the pointer, the column dims and a line marks where it lands, and the table scrolls when you near its edge. The settings list the columns in the table's order with a grip on each, and a column's options add Move left and Move right, with Alt+Shift+Up and Down in the settings for the keyboard. Pinned columns reorder among themselves. The order is TanStack's `columnOrder`, and Reset columns clears it. [Column order](/docs/components/base/data-table#column-order).

**Data Table polish.** Heads are taller (40px at the default density) and their labels lighter. A cell of tags no longer scrolls on its own: tags that don't fit fade out at the end and the cell names them all on hover, so scrolling sideways over the table always moves the table. Pinned columns now sit above the rows that scroll under them: the line at their edge is drawn on the pinned cells, so content never shows through it, and a soft shadow replaces the fade.

**Faster updates in Advanced components.** File Tree reuses selection and expansion lookups, Syntax Highlight reuses unchanged code lines, Audio Player keeps waveform bars stable during playback and scrubbing, and Editor reuses its word count when the caret moves. These improvements cover web and React Native.

**Drawer and Sheet widths.** Top and bottom panels are centered and capped at 36rem on wider screens. They keep their full width on phones.

**Theme tabs in the User Menu.** `UserMenuTheme` adds a Theme row to the menu with light, dark and system as small tabs. The pill slides to the picked one and the page reveals from it with Theme Toggle's blurred circle, or any other `variant`. It comes with `useThemePreference`, the same behaviour for tabs of your own. React Native has the row without the page reveal.

**Gaps in nested hover lists.** The gap around a list inside another list (the theme row in a menu) no longer lights or presses the outer list's nearest row.

**App Nav icons.** On Base UI, rows and the phone tab bar show their icons again: the default link's own text was replacing them, so an icon rail showed cut-off labels. On Radix, the tab bar no longer prints each label twice. A `renderLink` that returns a link with text now works in every base. If you added App Nav or App Shell after November 18, update `app-nav`.

**App Shell panel tabs.** In a panel under 360px, a view without an icon keeps its name instead of showing an empty tab.

**App Shell swap panels.** On phones, a panel that takes the whole screen sits on the page surface, and the main column behind it leaves the tab order and the accessibility tree.

**Event Calendar overlaps.** Events at the same time stand side by side in the day and week views, so none covers another's title.

**Chat bubbles hug their text.** A wrapped bubble no longer leaves a wide empty strip beside its lines.

**App Shell window dragging.** On macOS, drag the frame above the inset main column to move the window. Tabs and their controls remain clickable.

**Desktop sidebar toggle.** The App Shell’s sidebar toggle icon is slightly larger next to the window controls.

**Calmer resize edge tooltip.** The sidebar's resize edge waits 900ms before its Drag and Click hint opens, so a pointer passing over it on the way to the page no longer shows it. Sliding off a sidebar row onto the edge no longer opens the hint at once either.

**Resize lines beside cards.** With the inset sidebar, the line that shows when you hover the resize edge traces the main card's side, rounded corners included, instead of running straight across them from the top of the window to the bottom. With the floating sidebar, it traces the sidebar card's outer side. The App Shell panel's resize edge does the same beside the inset sidebar, tracing the panel card's inner side. In right-to-left layouts the resize edge now sits on the sidebar's edge, as it does left to right.

**App Shell panel resizing.** The panel's resize edge can be grabbed again: it had no height, so dragging it selected text instead. Dragging stops at the widest the panel can be while the main column keeps its minimum width, instead of turning the panel into an overlay that disappears.

**Tab Strip rename.** Base UI and Radix focus the inline field after a rename starts. Tab Strip now passes Biome's autofocus rule while keeping keyboard renaming.

**App Shell across platforms.** Tauri’s macOS window controls line up with Electron in the default layout, and the window material follows the light or dark theme. The pinned Details button stays visible in WebKit.

**Smoother chart hover.** Charts redraw only the crosshair, highlight and tooltip as the pointer moves, so hovering a large Candlestick or Heat Calendar no longer redraws every candle or day. `onActiveChange` now fires when the inspected mark changes, not on every pointer move or React Native drag event. Status Bar lifts a copy of the inspected pill that glides along the bar, and the other pills dim to 40%, so hovering no longer lays out the whole page on every step.

**Chart readouts fade out.** When the pointer leaves a chart or you press Escape, its tooltip, crosshair, dots, band and lifted day or pill fade out on the tooltip's exit timing instead of vanishing, and the tooltip shrinks slightly toward its mark. Coming back during the fade picks up the same readout without a second entrance. Dimming still clears at once. On React Native, the overlays fade out when you lift your finger.

**Chart tooltips grow from their mark.** The tooltip grows and shrinks from the edge facing the mark it describes, as popups grow from their trigger. The positioner carries `data-placement` (`after`, `before` or `above`).

**Charts under Reduce Motion.** With Reduce Motion on, charts appear fully drawn and fade in, instead of popping in when scrolled into view. Dimming and highlight washes still fade; only sweeps, growth, glides and morphs are dropped. The same holds on React Native, where the crosshair, dots and tooltip also keep their fade.

**One dim level for charts.** Spotlit and inspected marks dim the others to 40% on the hover timing in every chart, on the web and React Native. Treemap cells keep their lighter dim so their labels stay readable.

**Steadier Sankey and Bump hover.** Moving across the gaps between Sankey ribbons keeps the last ribbon lit and its tooltip in place, instead of flashing the whole diagram back to full strength. On Bump Chart, the spotlight hands over from one line to the next without lighting every line in between, and the tooltip stays on a line: the one you pointed at, or rank 1 when you use the keyboard.

**Charts morph as one.** When the data changes or the legend hides a series, leaving marks fade out as they shrink instead of stopping at the dim level and popping. Bump Chart names ride their lines to new ranks and down with a hidden series, Funnel and Sankey labels fade with their stage or node, and the Radial Chart's centre counts up with its first ring. Tooltips, crosshairs and lifted marks travel with the drawn marks during a morph instead of arriving first. On React Native, names, the radial centre and tooltips follow the morph, leaving marks fade to the dim level as they shrink, and Funnel and Sankey labels fade with their stage or node.

**Donut centre and value list.** Moving across slices swaps the Donut Chart's centre value through a soft blur, so two numbers never smear together. The value list's share bars open with the ring on its timing and finish with it, then resize smoothly when the data changes, on the web and React Native.

**Chart frames fade in.** Gridlines and axis labels fade in once when a chart first draws, instead of appearing at full strength while the marks are still drawing. Radar's grid and Heat Calendar's month and weekday labels fade the same way, on the web and React Native.

**Lifted marks grow out of their mark.** Heat Calendar's lifted day and Status Bar's lifted pill grow from the size of their mark as they fade in where the pointer lands, then glide from mark to mark without growing again. With Reduce Motion on, they fade in at full size.

**Tidier toasts.** Toast and Sonner share one width, 338px at the default density, instead of 384px and 356px. One line is 40px tall, with or without an action. The action sits beside text that leaves it room and under text that doesn't, and the status icon stays on the first line. Long titles and descriptions stop at two and three lines, long words break instead of running out of the toast, and hover, focus or a tap opens the full text. The close button moved to the corner, where it shows on hover, focus and touch. Toast takes a custom icon or avatar in `data.icon`, `ToastAction` defaults to the `secondary` button, and Sonner's `closeButton` is on by default and can be turned off. The base `sonner` item takes the same look.

**Rich Text Editor fits its container.** The selection bar, link field, keyboard bar, Turn into and the language picker open in the browser's top layer, so a card, dialog or scrolling panel around the editor no longer crops them. The selection bar stays within the editor and on screen, keeps clear of the toolbar, waits for the pointer to let go, and hides while its text is scrolled out of view. The toolbar keeps to one row at any width: commands without room move to a More menu, and a narrow editor folds the heading buttons into Turn into. The editor also shrinks inside grid and flex parents, where its toolbar, a long line of code or a wide table used to hold it open past the edge. The table's actions wrap instead of hiding Done and stay in view in a tall table, whose cells keep their borders while you edit. A toolbar can be made sticky in a long document, the Quote shortcut reads as a period, and Escape in the link field no longer closes the dialog around the editor.

**Toast motion.** Toasts fade and grow in from their edge and leave faster than they arrive. A stack steps back and narrows to the toast in front, opening and closing as one, and a toast that changes type (loading to success) changes height in place while its new content fades in. With Reduce Motion on, only the fades remain. On React Native, a new toast no longer takes the size of the one it covers, and an open stack no longer times out while it's being read.

**Pie Chart rests as one disc.** Slices meet edge to edge with square corners instead of keeping a 2px gap, and the slice you point at lifts out of the pie, on the web and React Native. Donut Chart keeps its gaps and rounded slices.

**React Native chart motion.** The Pie and Donut slice lift, the Line and Area draw-in and every dim run on the UI thread instead of redrawing the chart each frame, and a scrub on Line, Area, Bar or Composition no longer redraws its marks. The lift glides on the same quick timing as the website, and dimmed marks fade instead of snapping. Scrub ticks are at least 40ms apart: a fast scrub across a dense chart gives distinct ticks instead of a buzz, and the mark you stop on always ticks. In apps that enable React Native's IntersectionObserver, a chart's draw-in waits until a quarter of it is on screen.

## Blocks

**Browse and preview blocks.** The Blocks gallery has category filters and light and dark previews. Each block has a shareable page with an install command, source files, component links and a live preview at desktop, tablet and phone widths. Existing block links still resolve.

**Redesigned application screens.** Finance puts cash and accounts side by side. Mail gives the open thread the main column and keeps the inbox in a resizable panel. Assistant groups its work and opens artifacts beside the transcript. Messenger groups replies and adds conversation details. Calendar gives event details and RSVP their own panel. The authentication screens share the same form layout across steps.

**Settings, Members, Billing and Onboarding.** Add `settings-01`, `members-01`, `billing-01` or `onboarding-01` for workspace settings, invitations and roles, plan and invoice management, or a guided setup with a live workspace preview.

**Project board.** Add `board-01` for a ticket board that fills the page: projects and saved views in the sidebar, filters, people and rows over tinted columns, a new ticket form on `C`, and each ticket beside the board with its properties, sub-tasks, comments and history.

**Assistant upgrades.** If you previously installed `assistant-01`, its old `assistant-tool-call.tsx` can be removed after updating. The revised transcript uses grouped work steps.

## Kanban

Kanban, Properties and Record View for React web and React Native, over your own records and storage.

- **Kanban:** drag anywhere on a card, with the slot it will land in, a stack for several cards, and columns that refuse a drop and say why. Arrow keys move between cards and ⌥⇧ with an arrow moves one. Columns have status glyphs, limits, colours and menus, rename with a double click, collapse to a rail or hide. One compact toolbar line searches, filters, groups, sorts and sets what cards show, and adapts to its width down to a phone. Cards show a cover from a files property, are added inline, selected with ⌘ or Shift click and edited together.
- **Properties:** 25 types read and edited as rows, with date ranges and times, number formats, files and pictures, durations and colors. Each label opens its property's settings, drags to reorder, can hide when empty, and chooses whether cards show it. Values are validated, and apps add types of their own with settings, editors and rules.
- **Record View:** a side panel over a live board, a centred dialog or a full page, with a title edited in place, a cover, and loading, missing and error states.
