---
title: November 2026 - Tab Strip on phones and React Native fixes
description: On React Native phones the Tab Strip shows the active tab and a tab count, either of which opens a sheet of every tab as a card. Message Scroller opens at the start, and the editor's native view registers in every install.
date: 2026-11-10
---

- **A tab switcher on phones.** A phone's width fits about one and a half tabs, so on React Native phones the Tab Strip shows only the active tab, on a raised pill, and a count of open tabs. Tapping either opens a sheet with every tab as a card: tap a card to switch to it, tap × to close it, or long press it for the tab's menu. The sheet also has New tab and Done, so `TabStripNew` draws nothing on a phone. Tablets keep the full strip, and the API is the same, so existing code needs no changes.
- **The React Native example matches the desktop one.** Its sidebar is the same component explorer: an overview, then a row per component group that holds its components. Each component opens in a tab, and the Details panel has its install command.
- **Message Scroller opens at the start.** With `defaultScrollPosition="start"`, a React Native transcript longer than the first batch of messages it renders used to open part of the way down. It now opens on the first message, and `scrollToStart()` reaches it too.
- **The editor's native view registers when installed through a link.** `@fabricator-ui/editor-native` names its podspec for Expo, so a `file:` or `link:` install no longer fails with "native component is not registered".
- **A roomier revealed sidebar on phones.** With `mobileSidebar="reveal"` the sidebar takes the screen but a 72px strip of the page, on the web and on React Native, where it used to stop at 18rem. The page in that strip has a screen's rounded corners, continuous on iOS. `--sidebar-width-mobile` (`widthMobile` on React Native) now sets only the sheet's width.
- **Sidebar rows a little shorter on phones.** On React Native they're 40pt at a phone's density, down from 44.
- **Grouped fields keep their whole frame in focus.** On React Native an input or textarea inside an Input Group (Date Picker, Search, Combobox, Month Input) painted its own focus fill over the group's top and bottom border. The group now draws the frame and its focus alone, as on the web.
- **Fields stay above the keyboard.** On iOS, `AppShellContent` makes room for the keyboard and scrolls the focused field into view, and a tap on a button works while the keyboard is up.
- **The editor's keyboard bar floats on iOS.** With the keyboard up, the Rich Text Editor's formatting bar stays a rounded capsule a few points above iOS's floating keyboard, where it used to dock square across its top. Its buttons are pills, and a divider sets Hide keyboard apart from the commands that scroll. Android keeps the docked bar on its full-width keyboard.
- **Default density fits a finger on phones.** On React Native, picking Default on a phone gives the tablet's step: 40px controls and 15px text, a step under the phone's spacious base. It used to give the website's pointer sizes, 36px controls and 13px text, so the sidebar and every control came out too small.
