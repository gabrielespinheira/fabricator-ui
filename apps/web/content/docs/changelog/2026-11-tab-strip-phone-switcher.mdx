---
title: November 2026 - Tab Strip on phones and React Native fixes
description: On React Native phones the Tab Strip shows the active tab with a tab count, which opens a sheet of every tab as a card. Message Scroller opens at the start, and the editor's native view registers in every install.
date: 2026-11-10
---

- **A tab switcher on phones.** A phone's width fits about one and a half tabs, so on React Native phones the Tab Strip shows only the active tab, on a raised pill with a count of open tabs at its end. Tapping it opens a sheet with every tab as a card: tap a card to switch to it, tap × to close it, or long press it for the tab's menu. The sheet also has New tab and Done, so `TabStripNew` and `TabStripOverflow` draw nothing on a phone. Tablets keep the full strip, and the API is the same, so existing code needs no changes.
- **The React Native example matches the desktop one.** Its sidebar is the same component explorer: an overview, then a row per component group that holds its components. Each component opens in a tab, and the Details panel has its install command.
- **Message Scroller opens at the start.** With `defaultScrollPosition="start"`, a React Native transcript longer than the first batch of messages it renders used to open part of the way down. It now opens on the first message, and `scrollToStart()` reaches it too.
- **The editor's native view registers when installed through a link.** `@fabricator-ui/editor-native` names its podspec for Expo, so a `file:` or `link:` install no longer fails with "native component is not registered".
- **A roomier revealed sidebar on phones.** With `mobileSidebar="reveal"` the sidebar takes the screen but a 72px strip of the page, on the web and on React Native, where it used to stop at 18rem. The page in that strip has a screen's rounded corners, continuous on iOS. `--sidebar-width-mobile` (`widthMobile` on React Native) now sets only the sheet's width.
- **Sidebar rows a little shorter on phones.** On React Native they're 40pt at a phone's density, down from 44.
- **Grouped fields keep their whole frame in focus.** On React Native an input or textarea inside an Input Group (Date Picker, Search, Combobox, Month Input) painted its own focus fill over the group's top and bottom border. The group now draws the frame and its focus alone, as on the web.
- **Fields stay above the keyboard.** On iOS, `AppShellContent` makes room for the keyboard and scrolls the focused field into view, and a tap on a button works while the keyboard is up.
- **The editor's keyboard bar floats on iOS.** With the keyboard up, the Rich Text Editor's formatting bar stays a rounded capsule a few points above iOS's floating keyboard, where it used to dock square across its top. Its buttons are pills, and a divider sets Hide keyboard apart from the commands that scroll. Android keeps the docked bar on its full-width keyboard.
- **Default is the native default density.** React Native apps start on Default, and `FabricatorRoot` sizes it for the device: a phone's 44px controls and 15px text, a tablet's 40px. Compact and Spacious are a step either side (40px and 52px on a phone, 34px and 44px on a tablet), where they used to give the website's pointer sizes, which came out too small for a finger.
- **A slimmer bottom nav on phones.** The App Shell's `AppShellBottomNav` rows are 48px on a phone, down from 56, with medium-weight labels. Under the floating and glass capsules the page now quiets toward the main column's colour, as iOS's scroll edge effect does, so page text no longer reads through the bar. The App Shell options call it Bottom nav, after the component, and list Glass, the default, first: Glass, Floating, Flat.
- **A fresher effort slider.** Model Picker's effort fill now runs from sky blue to a soft violet, in the info role's chroma at a lighter tone, where it used to darken to purple and turn magenta at the top level on React Native. The thumb is the Slider's white knob, and the level dots on a chosen fill are light. The web and React Native draw it the same.
- **Popovers keep clear of the status bar.** On React Native a popover that has no room on its side opens on the other one, and none runs under the clock, the island or the home indicator, as Dropdown Menu already did.
- **One-line placeholders in the Chat Input pill.** On iOS a long placeholder in the pill truncates on its line, where it could wrap and grow the pill to two lines.
- **Chat Input trays step back on React Native.** The goal, background tasks and queued messages behind the card each sit a step further in on their own surface, as on the web. On React Native they used to draw the same width with no fill, so each tray's edge showed through the one in front. A row's reading, such as a goal's status, now truncates past 45% of the row, on both platforms, so the title stays readable in a narrow tray.
- **A folding tray stack.** `ChatInputTrays` wraps a Chat Input's trays and folds them: only the front row shows, with the other rows peeking out behind it as up to two edges, so a long queue never grows the composer. Pressing the edges opens every row, and Show less folds them again. Tray rows are shorter too, 30px at the default density, with less padding around them. On the web and React Native.
