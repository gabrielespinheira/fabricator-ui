# Fabricator style specification

How the Fabricator style is built: the foundations (tokens), the rules every style map and override follows, and the look of every component. Read it before changing a style map, a token or an override. How to design products with the components is the job of the root [`DESIGN.md`](../../../../DESIGN.md); keep the two in step when a look or a rule changes.

Components keep their shadcn API (AGENTS.md, contract item 1); the Fabricator style changes only their look and interaction, and upstream styles keep their exact output.

Six systems carry the design: **surfaces**, **colour roles**, **density**, **motion**, **fluid hover** and **scrollbars**. Everything else follows from them.

## Rules for style maps and overrides

**Style maps**

1. Every placeholder a component uses has a rule in its style file; the build fails otherwise. Rules may change completely; placeholder names may not.
2. Sizes come from the density tokens (see [Density](#density)); `__tests__/density-usage.test.ts` enforces it.
3. Durations, curves and zooms come from the motion roles (see [Motion](#motion)); `__tests__/motion-usage.test.ts` enforces it.
4. Colour comes from the role tokens or the neutrals, and states are opacity steps of the fill (see [Colour roles](#colour-roles)).
5. Each rule opens with a comment on why it looks the way it does, under a `/* MARK: <Component> */` heading.
6. Where upstream source hard-codes a duration or a size, the rule overrides it with an important class (`duration-sheet!`); class merging keeps the source's class otherwise.

**Overrides**

1. Copy the upstream file from `registry/bases/<base>/ui/<name>.tsx` to `registry/fabricator/<base>/ui/<name>.tsx` and keep every export, prop, variant and `data-slot`. Changes are additive.
2. Keep the diff small and container-level; style through placeholders, not inline classes.
3. Import Fabricator libs with `@/registry/bases/<base>/lib/…` (`@/registry/bases/__base__/…` in `shared/`).
4. Add new registry dependencies to `fabricatorOverrides` in `registry.ts`; they apply only to bases with an override file.
5. Base UI first, then Radix (same behaviour), then React Aria. A base without an override keeps upstream behaviour with Fabricator styling.
6. A portalled part reads `useDensity()` and sets `data-density` (see [Density](#density)).

The preview and build loops (live CSS, compiled styles, mobile captures) are in AGENTS.md, "Seeing style changes on the site". Check every change in light and dark.

## Foundations

### Surfaces

An eight-level ladder. Light: `surface-1` (#FAFAFA, the page) and `surface-2` (#FCFCFC), then flat white from level 3 up, separated only by shadow. Dark: each level is a step lighter, from `oklch(0.205)` (#171717) to `oklch(0.402)` (#484848). **Surfaces have no borders: every `shadow-surface-N` starts with a 1px ring.**

**Shadows.** `--shadow-N` is a 1px ring in `--shadow-color` (6% black) plus N−1 drops of 1, 3, 6, 12, 24, 48 and 96px, each with a negative spread of half its blur. Dark adds an inset top highlight and ring (`--dm-*`) and an outer black ring at 12–22%.

**Base colour.** Every surface is calculated from `--surface-hue` and `--surface-chroma` (`surface-tint.ts`), both `0` (neutral) by default. Each level takes a share of the chroma. Light mode tints every level, from 44% at the page to 21.5% at level 8 (about half, as in dark), and lowers each level's lightness as the chroma grows, because colour needs room below white: at full strength the ladder spans 0.962 (page, about oklch(0.962 0.018)) to 0.981, still rising level by level; `--muted-foreground` darkens with it to stay AA. Dark mode keeps every lightness and carries the tint, tapering from 90% at level 1 to 55% at level 8. `--selected` and, on the site, `--muted` follow it. Every level stays in sRGB for any hue at the maximum chroma (0.04), which the tests check.

The `fabricator` preset writes `background`, `card`, `popover`, `sidebar`, `muted` and `muted-foreground` as literal colours (the CLI only maps literals to utilities). The site, the Colors page's generated CSS and `/init` (when a look tints the surface) point them at the surfaces instead (`SURFACE_PALETTE_LINKS`).

### Interaction tokens

- `bg-hover` (4% black / 6% white): hover and lit rows. `bg-active` (7% / 10%): pressed, selected rows, toggled on.
- `bg-tint` / `bg-tint-hover` (8% / 6.5% black, 25% / 20% white) and the opaque `bg-selected` exist for consumers; no style map uses them yet.
- `--overlay` is an RGB triple for `rgb(var(--overlay) / <alpha>)` (scrollbar thumbs, the switch's hover step).
- **Focus** is a 1px blue ring with no offset: `focus-visible:ring-1 focus-visible:ring-ring` (`--focus-ring`, #6B97FF in both themes; `ring-focus-ring` is the same colour). The exceptions, each for a reason:
  - Checkbox, radio and switch add `ring-offset-2 ring-offset-background`, so the ring clears the filled control.
  - Text fields (input, textarea, input group, input OTP, search) focus with a neutral ring, `ring-foreground/25` (`/30` on OTP slots), since the caret already marks focus. The select trigger turns blue on keyboard focus.
  - The slider draws a 1px `border-ring` circle 4px outside the thumb.
  - The user menu mark offsets its ring by 1px.
- **Invalid:** `aria-invalid:ring-1 aria-invalid:ring-destructive/50`; fields add a `bg-destructive/5` hover wash; messages and invalid labels are `text-destructive-text`.
- **Disabled:** `opacity-50 pointer-events-none`; buttons that stay focusable (`aria-disabled`) keep pointer events and show `cursor-not-allowed`.
- `border` is 12% of the foreground (softer than shadcn); dividers inside menus and tables are `border/60`.

### Palette (shadcn token names)

`primary`, `secondary` and `destructive` are colour roles (below); the `fabricator` preset writes them as literal colours at the role defaults, so `primary` is the foreground colour (near black, near white in dark) until a project sets a hue. `accent` equals `hover`. `ring` is the focus blue in every role. `input` is a solid grey; `chart-1…5` are a neutral ramp (Chart is excluded for now).

### Colour roles

Six roles: `primary`, `secondary`, `info`, `success`, `warning`, `destructive`. Each is one base colour held by `--<role>-hue` and `--<role>-chroma`, like the surface tint; strength 0 is neutral. Defaults: primary and secondary neutral; info 260/0.18, success 150/0.13, warning 70/0.1, destructive 25/0.19. Primary and secondary take any hue; the statuses keep to their family (`ROLE_HUE_RANGES`, clamped in the CSS too): info 215–275 (blue), success 125–175 (green), warning 45–100 (orange to yellow), destructive 10–50 (red to orange). One recipe makes the same tokens for every role:

- `bg-<role>` / `text-<role>`: the fill, for buttons, checked controls, icons and dots. `text-<role>-foreground` is text on it. Secondary's fill is a translucent tint (shadcn's meaning).
- `text-<role>-text`: coloured text on any neutral or tinted surface (AA 4.5:1). All coloured text uses it.
- `border-<role>-border` / `ring-<role>-border`: the hairline (30% of the fill, 32% in dark).
- `bg-<role>-surface-1…8`: a tinted ladder paired with the same `shadow-surface-N`. It has its own lightness steps (light 0.97 → 0.999, dark 0.215 → 0.412), and its chroma tapers as the levels rise (×1 → ×0.39). Light uses levels 1–2 for fills; dark starts at 3 so the tint reads.

Light: the fill moves from the foreground to lightness 0.48 as chroma reaches 0.06 (then only chroma grows), with white text; the text colour settles at 0.45. Dark: the fill goes from 0.97 to 0.74 (chroma at most 0.13), with dark text; the text colour settles at 0.85. The Colors page treats the most chroma a hue can hold with fill, text and border in sRGB as 100% strength (`roleMaxChroma`).

The foundations never define the shadcn names (`primary`, `primary-foreground`, `secondary`, `secondary-foreground`, `destructive`); the site and a look that changes a role point them at the recipe (`ROLE_PALETTE_LINKS`).

**States are one rule for every role**, opacity steps of the fill, so they work with any palette:

- Solid: `bg-<role> text-<role>-foreground hover:bg-<role>/90 active:bg-<role>/80`. Secondary: `hover:bg-secondary/80`, pressed back to full.
- Soft (destructive button, invalid washes, destructive bubble): `bg-<role>/12 text-<role>-text hover:bg-<role>/16 active:bg-<role>/20`.
- The pressed step also applies while a trigger's popup is open (`aria-expanded:`) and to React Aria presses (`data-pressed:`).
- Focus is the blue ring; disabled is `opacity-50`.

**Primary** drives the default button, links (`text-primary-text`), checked and indeterminate checkboxes and radios (`bg-primary`, mark in `primary-foreground`), the switch track when on (knob `primary-foreground`), progress, the slider range (`bg-primary/10 dark:bg-primary/15`), the selected calendar day, the workspace logo fallback and the tab strip's waiting dot. **Secondary** drives the secondary button. **Destructive** drives the destructive button and menu items, invalid fields and their messages.

Statuses (info, success, warning, destructive) have two contrasts:

- **Low** (default): the neutral panel (`bg-hover`, foreground text) with only the icon in `text-<s>`.
- **High:** `bg-<s>-surface-1 dark:bg-<s>-surface-3`, `ring-1 ring-inset ring-<s>-border`, description in `text-<s>-text`; the title stays foreground. The default variant at high contrast is `bg-active ring-border`.

Used by Alert (`variant` + `contrast`), Badge (status variants, always tinted) and Toast/Sonner (status icons in the fill). `error` is another name for `destructive`: the Alert and Badge `error` variants share its rules, and error toasts use its colour.

### Syntax colours

Eight tokens in the foundations colour code (`text-syntax-<name>`): `keyword`, `function`, `string`, `constant`, `type`, `tag`, and the neutrals `comment` and `punctuation`. Function takes info's hue and chroma, string success's, constant warning's and tag destructive's, so a retinted role retints the code, and a role at strength 0 turns its tokens to the foreground. Keyword (violet, 315/0.16) and type (cyan, 195/0.08) have no role and take their own `--syntax-<name>-hue` and `-chroma`. The neutrals take the surface tint, as muted text does.

Every colour is one slot of the role recipe, the same lightness at any hue so no token outshouts another: light 0.47 at 85% of the chroma (the roles' coloured text is 0.45), dark 0.78 with chroma capped at 0.11, which keeps every hue inside sRGB up to `roleMaxChroma`. Comment is 0.51 light, 0.70 dark; punctuation 0.42 and 0.80. The test sweeps every role setting for gamut and 4.5:1 on surfaces 1 to 4, tinted or not.

Kinds map to colours in the style map, not in the tokens: attributes take `constant`, keys and properties `function`, variables `tag`, regular expressions `type`, operators `punctuation`, markdown headings `keyword` semibold, links `function` underlined; added and removed lines use `success-text` and `destructive-text`. The docs' Shiki theme (`lib/shiki-fabricator-theme.ts`) maps TextMate scopes to the same tokens.

### Density

Three densities size every component (`density.ts`, tested in `__tests__/density.test.ts`): **compact** for dashboards, toolbars and dense tables, **default** for apps, **spacious** for websites and landing pages. Default lives in `:root`; `data-density="<name>"` on `<html>` or any element switches everything inside it, and the `density-<name>` utilities do the same from a class (so breakpoints work). `DensityProvider` renders that attribute on a `display: contents` wrapper and passes the density through React context; every portalled part (menus, select, combobox, popover, hover card, tooltip, navigation menu, dialog, alert dialog, sheet, drawer) sets `data-density` from it, so popups match the region they opened from. Toasts follow `<html>`.

Tokens are named after their default value:

| `--density-40`              | 32      | 40      | 48       | Tab strip, large avatars, media tiles                              |
| `--density-36`              | 28      | 36      | 44       | Controls, menu rows, table head, tab tracks                        |
| `--density-32`              | 28      | 32      | 40       | Sidebar rows, avatars, calendar cells, workspace logos             |
| `--density-28`              | 24      | 28      | 36       | Tabs and segmented items, sub-rows, status bar                     |
| `--density-24`              | 20      | 24      | 28       | Badges, chips, row actions, dialog padding                         |
| `--density-20`              | 16      | 20      | 24       | Switch track height, Kbd, sidebar badges                           |
| `--density-16`              | 12      | 16      | 20       | Button padding, card spacing, dialog and sheet gaps                |
| `--density-12`              | 10      | 12      | 14       | Tab, accordion, table and toggle-group padding; popover padding    |
| `--density-10`              | 8       | 10      | 12       | Input, select, toggle and badge padding                            |

| `--density-icon-16` / `-14` | 14 / 12 | 16 / 14 | 18 / 16  | Icons / breadcrumb separators, nav chevrons                        |

The other steps (`--density-14`) follow the same scale.

**Never write fixed control sizes.** Write `h-(--density-36)`, `px-(--density-16)`, `gap-(--density-6)`, `text-(length:--density-text-13)`, `size-(--density-icon-16)`. They are CSS variables rather than theme keys because class merging only knows arbitrary values: `text-control` would read as a colour and drop next to `text-muted-foreground`, and `h-control` would never conflict with a consumer's `h-12`. Derived geometry is a `calc()` of tokens (menu insets: two row paddings plus an icon; the checkbox at the icon size plus 2px; sidebar actions centred on their row). The test catches exact `text-[11–16px]`, fixed `h-`/`size-`/`min-h-`/`min-w-` from 5 to 12, and fixed svg sizes 3.5, 4 and 18px; anything else relies on review (see [Known deviations](#known-deviations)).

**A `size` prop pins a control to a density.** `sm` adds `density-compact` (button, toggle, toggle group, select trigger, switch, search, tab strip; `icon-sm`), and `lg` adds `density-spacious` (button, toggle, toggle group, search; `icon-lg`); the default size follows the nearest density. Button `xs` and `icon-xs` stay a fixed 24px floor. On React Native a phone's base is spacious, where those pins would drop `sm` to 28pt and 12pt text and leave `lg` the same as the default, so at spacious `sm` is a step down (default: 36pt, 13pt) and `lg` a step up (`LARGE_DENSITY` in `registry/native/lib/density-scale.ts`: 52pt, 17pt); `useControlSize` applies it, and a control reaches its 44pt target through `getTouchSlop`. A tablet's window (768pt and up) has its own rung in place of spacious, which `FabricatorRoot` sets: 40pt controls and rows with the phone's 15pt text and 18pt icons, between the website's 36pt and the phone's 44pt, because there's room for lighter chrome and a tablet is read from further away. Its `sm` is 34pt and 14pt, its `lg` 48pt and 16pt, its `xs` 28pt and 13pt (`TABLET_DENSITY`, `TABLET_SMALL_DENSITY`, `TABLET_LARGE_DENSITY`). A density picked on purpose stays. Containers (card, item, attachment, avatar, sidebar rows) keep their own sizes as steps on the density scale, so they shrink and grow with it. Anything without a size prop takes `data-density` directly.

### Shape

Every corner comes from `--radius` (0.5rem). `rounded-lg` is `--radius` (8px): items, buttons, inputs, badges, tooltips and highlights. `rounded-xl` is `--radius` × 1.4 (0.7rem, about 11px): containers such as popups, cards, dialogs, alerts, tab tracks and the App Shell main column. Nesting is concentric: a `rounded-xl` container with `p-1` holds `rounded-lg` items. Small inner parts (input group buttons, chips, breadcrumb links, the tab strip close button) use `rounded-md`. Checkboxes are `rounded-[6px]`; switches, avatars, status dots, the Search button and slider thumbs are `rounded-full`.

**Pill** (the `radius-pill` item, or `shape=pill` in a look) sets `--radius: 1.25rem`: 36px controls become full pills (20px) and containers 28px, still concentric. The site applies it with `data-radius="pill"` on `<html>`. Style maps write `rounded-lg` and `rounded-xl`, so every corner follows `--radius`.

### Motion

Motion follows Emil Kowalski's guidance: ease-out for anything that enters or leaves, ease-in-out for things that move on screen, plain `ease` for colour; exits about 30% quicker than entrances; popups grow from their trigger, dialogs from the centre, nothing from below 0.9; buttons give to 0.97 when pressed; tooltips skip their animation once one is open, or when they open from focus. Tokens, speeds and utilities live in `motion.ts`.

**Roles.** Every animation belongs to a role and reads its tokens (the default speed shown):

| Role       | Covers                                                                              | Use                               | Default     |
| ---------- | ----------------------------------------------------------------------------------- | --------------------------------- | ----------- |
| feedback   | hover, colour, focus, icon stroke, weight                                           | `duration-feedback ease-feedback` | 150 / 100ms |
| press      | buttons and toggles while held (joined groups, input groups and disabled stay flat) | `motion-press`                    | scale 0.97  |
| glide      | the Fluid Hover highlight                                                           | `duration-glide ease-enter`       | 150 / 100ms |
| move       | indicators, thumbs, selection, checkmarks, progress, sidebar, panel widths, Search  | `duration-move ease-move`         | 250 / 180ms |
| tooltip    | tooltips                                                                            | `motion-tooltip`                  | 125 / 90ms  |
| popup      | menus, selects, comboboxes, popovers, hover cards, navigation menus                 | `motion-popup`                    | 180 / 120ms |
| dialog     | dialogs, alert dialogs; their scrims                                                | `motion-dialog`, `motion-scrim`   | 250 / 180ms |
| sheet      | sheets and drawers                                                                  | `motion-sheet`                    | 400 / 250ms |
| disclosure | accordion and collapsible panels                                                    | `motion-disclosure`               | 200 / 150ms |
| toast      | toasts                                                                              | `motion-toast`                    | 350 / 220ms |

**Speeds.** Four speeds set every token. Default lives in `:root`; `data-motion="<speed>"` on `<html>` or any element switches everything inside it (portalled popups follow `<html>`), `data-motion="off"` stops motion, and `--motion-scale` multiplies every duration on top.

| Speed     | For               | Durations          | Scales: press, tooltip, popup, dialog | Extras                                                                                           |
| --------- | ----------------- | ------------------ | ------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `smooth`  | Marketing sites   | about 1.5× default | 0.97, 0.96, 0.94, 0.94                | Expo-out entrances, a softer move curve, tooltips slide 4px, popups slide 6px through a 2px blur |
| `default` | Most products     | Emil's timings     | 0.97, 0.97, 0.95, 0.95                |                                                                                                  |
| `snappy`  | Apps used all day | about ¾ of default | 0.98, 0.98, 0.97, 0.97                |                                                                                                  |
| `instant` | Dense dashboards  | fades only         | 1, 1, 1, 1                            | Instant tooltips; moves end on ease-out                                                          |

Sheets take 500, 400, 300 and 200ms across the four.

- **Never write milliseconds, curves or zooms.** Use `motion-<surface>` for surfaces and `duration-<role>`, `duration-<role>-exit`, `delay-<role>` and `ease-enter|move|exit|feedback|drawer` for everything else. Arbitrary transitions use `calc(var(--motion-<role>) * var(--motion-scale, 1))`. `motion-usage.test.ts` fails on fixed durations, literal curves, fixed zooms and the retired tier names; it allows the Search clear button's `zoom-in-75`, a pop inside a field rather than a surface.
- The `motion-<surface>` utilities hold the whole recipe: enter and exit durations and curves (exit when `data-closed`, `data-state=closed`, `data-exiting` or `data-ending-style`), the scale the surface grows from, and its slide from the trigger side. They set `--tw-duration` and `--tw-ease`, which `animate-in`/`animate-out` and every `transition*` utility read, so they time keyframes and transitions alike. Popups pair them with `origin-(--transform-origin)` and `data-open:animate-in data-open:fade-in-0 data-closed:animate-out data-closed:fade-out-0`.
- Where the source hard-codes timing, the style map sets the role's tokens directly: the Base UI drawer runs on `duration-sheet! ease-drawer!` (exit scaled by `--drawer-swipe-strength`, no transition while swiping), toasts transition on `--motion-toast` (height on `--motion-feedback`), and the sheet scrim, item, message scroller and Sonner (`cn-sonner`) take their role's duration. Vaul (Radix Drawer) keeps its 500ms, which its JavaScript relies on.
- The command palette marks its panel `data-motion="off"`; the dialog scrim next to it follows (`has-[+[data-motion=off]]:[--motion-scale:0]`).
- Old names stay as aliases for consumers: `duration-fast|moderate|slow` (feedback, move, dialog) and `ease-spring`, `ease-spring-bounce` (the entrance curve). Fabricator code doesn't use them.
- Animate transform and opacity. Panel and Search widths are the deliberate exceptions, on the move timing.
- Reduced motion keeps fades and drops slides, zooms, blur and the press (foundations, at every speed).
- React Native reads the same tokens through `useMotion`, `useSurfaceAnimation` and `usePressScale` (`registry/native/lib/motion.ts`). Surfaces grow from the edge beside their trigger through `transformOrigin`. An `active:` class can only snap, so buttons draw their pressed step with `PressWash` and stateful fills (checkbox, radio, toggle) with `StateFill`, on the feedback timing; a control's text colour eases through `TextStyle eases`, and a text field's frame through `useFieldFrame`. Popup blur isn't drawn: React Native has no blur filter on iOS.

### Typography and weight

Inter with its optical-size axis (`opsz`). `font-medium` is 450 and `font-semibold` 550 in the Fabricator palette.

On React Native, text is Inter through `--font-sans`: `font-medium` and `font-semibold` pick the static 500 and 600 cuts, the closest to 450 and 550, and there is no optical-size axis. `Text` sets the website's inherited 1.5 line height itself, unless a `leading-*` or a named size chose one. A project embeds the fonts through `expo-font` (the React Native installation page has the config); without them it falls back to the system font.

Inputs and textareas are `text-base` (16px) below `md` so iOS doesn't zoom into them, and 13 from `md`. Descriptions are `text-muted-foreground`.

**Hover changes colour (muted → foreground) and icon stroke (1.5 → 2); weight changes only for persistent state** (checked, selected, open accordion); tabs and tab strip tabs never change weight, only colour and the pill. Resting labels in lists are `text-muted-foreground` (tab triggers `text-foreground/65`, sidebar labels `text-foreground/80`); lit, selected or open ones are `text-foreground`. For weight changes that must not shift layout, use `weight-normal` / `weight-medium` / `weight-semibold` / `weight-bold` (Inter `wght` 400/450/550/700 paired with `opsz` 14/15/18/25) with `transition-[font-variation-settings]`, e.g. `weight-normal data-checked:weight-semibold`; the sidebar, App Shell and switchers use them. `text-box-trim` centres text optically in fixed-height controls.

### Scrollbars

Global native scrollbars are thin and low-contrast on fine pointers (foundations CSS); `scrollbar-hide` and `no-scrollbar` remove them. ScrollArea: a 10px track with `p-px` and a centred thumb, 4px at rest and 6px on hover, `rgb(var(--overlay)/0.08)` → `/0.12` → `/0.16` while dragging, rounded. The scrollbar fades in on the move timing on hover or scroll, and out on `duration-move-exit` after `delay-move` (the Radix scrollbar fades on the feedback timing). Its viewport, the sidebar content and the message scroller add `scroll-fade`; the tab strip list adds `scroll-fade-x`. Touch keeps native scrolling.

### Rendering

Everything should land on whole pixels and render smoothly.

- **Text:** the foundations set grayscale anti-aliasing (`-webkit-font-smoothing: antialiased`, `-moz-osx-font-smoothing: grayscale`), `text-rendering: optimizeLegibility`, kerning, `font-optical-sizing: auto` and `font-synthesis: none` (no faux bold or italic) on `html`, and remove the tap highlight on touch.
- **No half-pixel transforms at rest:** a `translate(-50%)` lands on half pixels for odd sizes and blurs text. Dialogs and alert dialogs are centred with `inset-0 m-auto h-fit` instead; enter/exit zooms still animate `transform`, which is back to `none` at rest.
- **Fluid Hover** positions its highlight from `offsetTop`/`offsetLeft`, which are whole pixels.

### Translucent menus

A project with `menuColor: "default-translucent"` gets the install-time marker `cn-menu-translucent` resolved on menu content (dropdown, context, menubar, select, combobox): `bg-surface-3/80` with `backdrop-blur-xl backdrop-saturate-150` on a `::before`, so the popup keeps its own motion. Rows keep the translucent `bg-hover` highlight.

### Sounds

`<SoundEffects />` plays Web Audio sounds for every component, chosen from `data-slot`, the ARIA role or `data-sound` (`data-sound="none"` silences a subtree), so components need no changes. Each family has its own material: buttons are wood, selection controls a mechanism, switches liquid, rows and links glass, tabs bells; popups, dialogs, sheets and toasts each have their own. Triggers that open a popup, tooltips and the sidebar toggle stay silent; surfaces sound only right after a click or key press. There are no audio files: a new sound is a synthesis recipe in `sound-recipes.ts`, and third-party audio needs a licence that allows MIT redistribution.

On React Native the recipes are the same, and a surface only sounds within a second of a touch. React Native has no Web Audio, so `lib/sound-synth.ts` renders each recipe to a WAV in the cache the first time it's needed, sample for sample with the website's graph, and `expo-audio` plays it. Each name also has a haptic (`sounds-model.ts`). Sounds mix with other apps' audio and follow the ring switch. Controls call `useFeedback()`; surfaces use `useMountFeedback` or `useSurfaceFeedback`. A press's sound waits a frame, so a surface it opened replaces it, as on the website.

## Fluid hover

One `bg-hover` highlight glides to the item nearest the pointer (no dead zones in gaps; gap clicks go to the lit item). It fades in where it first appears, glides within a session, and fades out when the pointer leaves. The primitive's keyboard highlight (`data-highlighted`, `aria-selected`…) moves the same highlight while the pointer is outside. A separate `bg-active` selection background slides between selected items on the move timing. Disabled items are skipped. Reduced motion keeps the fades and drops the travel.

### Wiring a container (override pattern)

```tsx
import { FluidHoverHighlight, FluidHoverSelection, useFluidHover, useMergedRef } from "@/registry/bases/<base>/lib/fluid-hover"

const fluid = useFluidHover<HTMLDivElement>({
  items: '[role="menuitem"]',          // selector for items inside the container
  highlighted: "[data-highlighted]",  // primitive's keyboard highlight (optional)
  selected: "[data-checked]",         // gets the sliding selection background (optional)
  axis: "y",                          // "x" for strips, "xy" for grids, "auto" follows the orientation attribute (tabs)
  // disabled: items to skip (default `[data-disabled], [aria-disabled="true"], :disabled`)
  // gapClick: a click between items goes to the lit item (default true)
})
const mergedRef = useMergedRef(fluid.attach, ref)

<Primitive.Container ref={mergedRef} {...fluid.props} {...props}>
  <FluidHoverSelection selection={fluid.selection} />   {/* optional, before the highlight */}
  <FluidHoverHighlight hover={fluid.hover} />
  {children}
</Primitive.Container>
```

- The container must be `relative isolate` (put it in its style rule); overlays sit at `-z-10` inside it, under the items.
- The container gets `data-fluid-hover`; the lit item gets `data-fluid-hover-active`.
- In the style map, items keep a fallback hover (`data-highlighted:bg-hover`) and turn it off inside a fluid container: `in-data-[fluid-hover]:data-highlighted:bg-transparent`. The lit item is styled with `data-fluid-hover-active:text-foreground data-fluid-hover-active:[&_svg]:stroke-2`. Selected items with a sliding selection background drop their own background inside the container the same way.
- Override the highlight or selection look per component with `className` (tabs: `className="cn-tabs-selection"`), and add that placeholder to the component's style file. The defaults live in `fluid-hover.css`: the highlight is `bg-hover rounded-lg` on `duration-glide`, the selection `bg-active` on `duration-move ease-move`.
- Each container has its own highlight; split a list at its separators so the highlight never crosses groups. A nested container (a submenu) keeps its own.
- Used by: menus (dropdown, context, menubar), select, combobox, command, navigation menu, tabs, tab strip, toggle group (the selection only in single-select groups), sidebar menu, accordion triggers, table rows. Skip it where a wrong click would hurt or items are far apart.

### On touch

A finger has no hover, so it takes the pointer's place (`registry/native/lib/fluid-hover.tsx`). A press fades the highlight in where it lands, holding long enough to be seen on a quick tap, and it fades out in place on release. Another press before it has faded glides from there. Where `track` is set, dragging moves the highlight from row to row with a tick on each, and letting go activates the lit row; a release far from the rows does nothing. Strips use `drag`. Lists that fit use `drag`, and lists that scroll use `hold` so a flick still scrolls (`FluidHoverScrollList` chooses). Rows in anything but `drag` wait 90ms to light, as iOS tables do, so starting a scroll doesn't flash the row under the finger. Tabs preview the next selection: the selection dims to 85% while another tab is lit, and the highlight hides over the selected one. The phone tab bar is a strip too, flat or a floating capsule with a sliding pill. Everything else follows the rules above: the same tokens, timings and lit styles, with the highlight's position driven on the UI thread.

## Not in the library

The Fabricator library doesn't ship controls that only restyle a raw native element. `FABRICATOR_EXCLUDED_ITEMS` in `registry.ts` leaves them out of the published registry and points dependencies at the replacement: Native Select → Select. ## Known deviations

Places where the code doesn't follow this spec yet. Fix the code, then delete the line.

- `AppShellPageTitle` is a fixed `text-2xl` (24px), outside the density scale and different from the 28px display role on the typography page. Pick one page-title size and give it a token.
- Navigation menu triggers keep the source's fixed `h-9`, so they ignore density, and the Radix navigation menu override doesn't read `useDensity()`.
- Fixed sizes the density test misses: the Empty description (`text-[13px]/relaxed`), the accordion chevron (`size-4`), and svg `size-3` in badge, kbd and avatar. Extend `density-usage.test.ts` to catch them.
- `native-select.css` (still fixed `h-9 … text-[13px]`, skipped by the density test) and `chart.css` style excluded items. Delete them, or note why they stay until Chart returns.
- `bg-tint`, `bg-tint-hover` and `bg-selected` are defined but used by no style map.
- React Aria has no Menubar or Navigation Menu (upstream ships neither for that base).
- The Video Player's chrome is raw white on black scrims (`text-white`, `bg-white/15`, `from-black/70`) in both themes: it sits over arbitrary footage, which no theme token stays legible on.
- The Color Picker's area and slider thumbs draw raw white and black edges (`border-white`, `rgb(0 0 0/…)`): they have to stay visible on any picked color, which no theme token guarantees. The hue track's rainbow is literal hex for the same reason.
