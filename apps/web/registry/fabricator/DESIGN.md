# Fabricator design language

The Fabricator style adapts [Fluid Functionalism](https://www.fluidfunctionalism.com) by Micka Touillaud (MIT, [source](https://github.com/mickadesign/fluid-functionalism)) onto Fabricator's shadcn-compatible components. The components keep their shadcn API (AGENTS.md, contract item 1); only their look and interaction change, and only in the Fabricator style.

Four systems are the basement of the design: **surfaces**, **motion**, **fluid hover** and **scrollbars**. Everything else follows from them.

## Where things live

| What                                                                                | Where                                                                                                                               |
| ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Tokens (surfaces, shadows, hover/active, focus, motion, scrollbars) and the palette | `registry/fabricator/foundations.ts` → the `foundations` registry item, the `/init` payload, and the generated `app/fabricator.css` |
| Colour roles (primary, secondary, info, success, warning, destructive)              | `registry/fabricator/color-roles.ts`, contrast-tested in `__tests__/color-roles.test.ts`; spread into the foundations and palette   |
| Style map: one file per component                                                   | `registry/styles/fabricator/<component>.css` → assembled into `registry/styles/style-fabricator.css` by the build                   |
| Fluid hover                                                                         | `registry/fabricator/shared/lib/fluid-hover.tsx` (registry item `fluid-hover`)                                                      |
| Behaviour overrides (TSX)                                                           | `registry/fabricator/<base>/ui/<component>.tsx`, a copy of the upstream source with additive changes                                |
| Override dependencies                                                               | `fabricatorOverrides` in `registry/fabricator/registry.ts`                                                                          |

## Foundations

### Surfaces

An eight-level ladder. Light: `surface-1` (#FAFAFA, the page) and `surface-2` (#FCFCFC), then flat white from 3 up, separated only by shadow. Dark: each level is 7 per channel lighter (#171717 → #484848) and the shadow adds an inset top highlight and ring. **Surfaces have no borders: every `shadow-surface-N` starts with a 1px hairline ring.**

**Base colour.** Every surface is calculated from `--surface-hue` and `--surface-chroma` (`registry/fabricator/surface-tint.ts`), both `0` (neutral) by default. Each level takes a share of the chroma. Light mode tints every level, from 44% at the page to 21.5% at level 8 (about half, as in dark), and lowers each level's lightness as the chroma grows, because colour needs room below white: at full strength the ladder spans 0.962 (page, about oklch(0.962 0.018)) to 0.981, still rising level by level; `--muted-foreground` darkens with it to stay AA. Dark mode keeps every lightness and carries the tint, tapering from 90% at level 1 to 55% at level 8. `--selected` and, on the site, `--muted` follow it. Every level stays in sRGB for any hue at the maximum chroma (0.04), which the tests check. The `fabricator` preset still writes `background`/`card`/`popover`/`sidebar`/`muted`/`muted-foreground` as literal colours (the CLI needs them); the site and the Colors page's generated CSS point them at the surfaces (`SURFACE_PALETTE_LINKS`).

| Element                                                       | Classes                                                                                                                                      |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Page                                                          | `bg-background` (= surface-1)                                                                                                                |
| Card (default)                                                | transparent, borderless; raised cards use `bg-surface-3 shadow-surface-3`                                                                    |
| Popover, dropdown, select, combobox, context menu, hover card | `bg-surface-3 shadow-surface-3 rounded-xl`                                                                                                   |
| Dialog, alert dialog                                          | `bg-surface-5 shadow-surface-5 rounded-xl`                                                                                                   |
| Sheet, drawer                                                 | `bg-surface-3 shadow-surface-3` (edge = shadow ring, no border)                                                                              |
| Tabs active pill                                              | `bg-surface-4 shadow-surface-4`                                                                                                              |
| Sidebar                                                       | `bg-sidebar` (= surface-2); inset main area `bg-surface-2 shadow-surface-2 rounded-xl`; peek card `bg-surface-3 shadow-surface-3 rounded-xl` |
| Tooltip                                                       | inverted: `bg-foreground text-background`                                                                                                    |

Overlays/scrims: `bg-black/40 dark:bg-black/80`.

### Interaction tokens

- `bg-hover` (4% black / 6% white): hover and lit rows. `bg-active` (7% / 10%): pressed, selected rows, toggled-on.
- `bg-tint` / `bg-tint-hover`: translucent neutral fill.
- `--focus-ring` / `ring-ring` (#6B97FF, both themes): **focus is a 1px blue ring with no offset**: `focus-visible:ring-1 focus-visible:ring-ring`. Switch adds `focus-visible:ring-offset-2 focus-visible:ring-offset-background`.
- Invalid: `aria-invalid:ring-1 aria-invalid:ring-destructive/50`; hover wash `bg-destructive/5`; messages `text-destructive-text`.
- Disabled: `opacity-50 pointer-events-none`.
- `border` is 12% foreground (softer than shadcn); dividers in menus are `bg-border/60`.

### Palette (shadcn token names)

`primary`, `secondary` and `destructive` are colour roles (below); the `fabricator` preset writes them as literal colours at the role defaults, so `primary` is the foreground colour (near-black / near-white) until a project sets a hue. `accent` equals `hover`. `ring` is the focus blue in every role.

### Colour roles

Six roles: `primary`, `secondary`, `info`, `success`, `warning`, `destructive` (`registry/fabricator/color-roles.ts`, contrast-tested in `__tests__/color-roles.test.ts`). Each is one base colour held by `--<role>-hue` and `--<role>-chroma`, like the surface tint; strength 0 is neutral. Defaults: primary and secondary neutral; info 260/0.18, success 150/0.13, warning 70/0.1, destructive 25/0.19. Primary and secondary take any hue; the statuses keep to their family (`ROLE_HUE_RANGES`, clamped in the CSS too): info 215–275 (blue), success 125–175 (green), warning 45–100 (orange to yellow), destructive 10–50 (red to orange). One recipe makes the same tokens for every role:

- `bg-<role>` / `text-<role>`: the fill, for buttons, checked controls, icons and dots. `text-<role>-foreground` is text on it. Secondary's fill is a translucent tint (shadcn's meaning).
- `text-<role>-text`: coloured text on any neutral or tinted surface (AA 4.5:1). All coloured text uses it.
- `border-<role>-border` / `ring-<role>-border`: the hairline.
- `bg-<role>-surface-1…8`: the tinted ladder, the same eight levels as the neutral surfaces, paired with the same `shadow-surface-N`. Light uses surface 1–2 for fills; dark starts at 3 so the tint reads.

Light: the fill moves from the foreground to lightness 0.48 as chroma reaches 0.06 (then only chroma grows), with white text. Dark: from 0.97 to 0.74 (chroma at most 0.13), with dark text. The Colors page treats the most chroma a hue can hold with fill, text and border in sRGB as 100% strength (`roleMaxChroma`).

The foundations never define the shadcn names (`primary`, `primary-foreground`, `secondary`, `secondary-foreground`, `destructive`); the site points them at the recipe (`ROLE_PALETTE_LINKS`).

**States are one rule for every role**, opacity steps of the fill, so they work with any palette:

- Solid: `bg-<role> text-<role>-foreground hover:bg-<role>/90 active:bg-<role>/80`. Secondary: `hover:bg-secondary/80`, press back to full.
- Soft (destructive button, invalid washes, destructive bubble): `bg-<role>/12 text-<role>-text hover:bg-<role>/16 active:bg-<role>/20`.
- Focus is always the 1px blue ring; disabled is `opacity-50`.

**Primary** drives the default button, links (`text-primary-text`), checked checkbox and radio (`bg-primary`, mark in `primary-foreground`), the switch track when on (knob `primary-foreground`), progress, the slider range (`bg-primary/10 dark:bg-primary/15`) and the selected calendar day. **Secondary** drives the secondary button. **Destructive** drives the destructive button and menu items, invalid fields and their messages.

Statuses (info, success, warning, destructive) have two contrasts, as on Fluid Functionalism's banner:

- **Low** (default): the neutral panel (`bg-hover`, foreground text) with only the icon in `text-<s>`.
- **High:** `bg-<s>-surface-1` (`dark:bg-<s>-surface-3`), `ring-1 ring-inset ring-<s>-border`, description in `text-<s>-text`; the title stays foreground.

Used by Alert (`variant` + `contrast`), Badge (status variants, always tinted) and Toast/Sonner (status icons in the fill). `error` is another name for `destructive`: the Alert and Badge `error` variants share its rules, and error toasts use its colour.

### Density

Three densities size every component (`registry/fabricator/density.ts`, tested in `__tests__/density.test.ts`): **compact** for dashboards, toolbars and dense tables, **default** for apps, **spacious** for websites and landing pages. Default lives in `:root`; `data-density="<name>"` on `<html>` or any element switches everything inside it, and the `density-<name>` utilities do the same from a class (so breakpoints work). `DensityProvider` (registry item `density`, `registry/fabricator/shared/ui/density.tsx`) renders that attribute on a `display: contents` wrapper and passes the density through React context; every portalled part (menus, select, combobox, popover, hover card, tooltip, navigation menu, dialog, alert dialog, sheet, drawer) sets `data-density` from it, so popups match the region they opened from. Toasts follow `<html>`.

|                                                          | Compact  | Default                    | Spacious  |
| -------------------------------------------------------- | -------- | -------------------------- | --------- |
| Control height (buttons, inputs, selects, **menu rows**) | 28px     | 36px                       | 44px      |
| Text                                                     | 12px     | 13px                       | 15px      |
| Icon                                                     | 14px     | 16px                       | 18px      |
| Horizontal padding: bounded controls / rows              | 10 / 6px | 12 / 8px (`px-3` / `px-2`) | 14 / 10px |
| Gap                                                      | 6px      | 8px (buttons 6px)          | 10px      |
| Segmented item / track padding                           | 24 / 2px | 28 / 4px                   | 36 / 4px  |

**Never write fixed control sizes.** Every token is named after its default value and resolves where it is used: `h-(--density-36)`, `px-(--density-16)`, `gap-(--density-6)`, `text-(length:--density-text-13)`, `size-(--density-icon-16)`. They are CSS variables rather than theme keys because class merging only knows arbitrary values: `text-control` would read as a colour and drop next to `text-muted-foreground`, and `h-control` would never conflict with a consumer's `h-12`. Derived geometry is a `calc()` of tokens (menu insets: two row paddings plus an icon; sidebar actions centred on their row). `registry/fabricator/__tests__/density-usage.test.ts` fails on fixed heights, text sizes and icon sizes in the style maps.

**A `size` prop pins a control to a density.** `sm` adds `density-compact`, `lg` adds `density-spacious` (button, toggle, toggle group, select trigger, switch, search; `icon-sm` / `icon-lg` too); the default size follows the nearest density. xs stays the fixed 24px floor. Containers (card, item, attachment, avatar, sidebar rows) keep their own sizes as steps on the density scale, so they shrink and grow with it. Anything without a size prop takes `data-density` directly.

Type roles at the default density: display 28, title 16 (dialog titles, `font-bold`), subtitle 14 (card titles), body 13, caption 12 (descriptions, group labels, errors); all but display follow the density. Descriptions are `text-muted-foreground`.

### Shape

Items, buttons, inputs, highlights: `rounded-lg` (8px). Containers (popups, cards, dialogs, tab tracks): `rounded-xl` (12px). Nesting is concentric: a `rounded-xl` container with `p-1` holds `rounded-lg` items. Checkboxes `rounded-[5px]`; switches, badges dots, avatars `rounded-full`.

### Motion

Motion follows Emil Kowalski's guidance: ease-out for anything that enters or leaves, ease-in-out for things that move on screen, plain `ease` for colour; exits about 30% quicker than entrances; popups grow from their trigger, dialogs from the centre, nothing from below 0.9; buttons give to 0.97 when pressed; tooltips skip their animation once one is open; nothing opened from the keyboard animates. The tokens, speeds and utilities live in `registry/fabricator/motion.ts`.

**Roles.** Every animation belongs to a role and reads its tokens:

| Role       | Covers                                                                  | Use                               | Default     |
| ---------- | ----------------------------------------------------------------------- | --------------------------------- | ----------- |
| feedback   | hover, colour, focus, icon stroke, weight                               | `duration-feedback ease-feedback` | 150 / 100ms |
| press      | buttons and toggles while held (joined groups stay flat)                | `motion-press`                    | scale 0.97  |
| glide      | the Fluid Hover highlight                                               | `duration-glide ease-enter`       | 150 / 100ms |
| move       | tab indicators, switch thumbs, selection, checkmarks, progress, sidebar | `duration-move ease-move`         | 250 / 180ms |
| tooltip    | tooltips                                                                | `motion-tooltip`                  | 125 / 90ms  |
| popup      | menus, selects, comboboxes, popovers, hover cards, navigation menus     | `motion-popup`                    | 180 / 120ms |
| dialog     | dialogs, alert dialogs; their scrims                                    | `motion-dialog`, `motion-scrim`   | 250 / 180ms |
| sheet      | sheets and drawers                                                      | `motion-sheet`                    | 400 / 250ms |
| disclosure | accordion and collapsible panels                                        | `motion-disclosure`               | 200 / 150ms |
| toast      | toasts                                                                  | `motion-toast`                    | 350 / 220ms |

**Speeds.** Four speeds set every token: `smooth` (marketing sites: longer, expo-out, popups from 0.94 with a 6px slide and a 2px blur), `default` (Emil's timings), `snappy` (apps used all day, about a quarter quicker) and `instant` (dense dashboards: fades only, no zoom or press, instant tooltips). Default lives in `:root`; `data-motion="<speed>"` on `<html>` or any element switches everything inside it (portaled popups follow `<html>`), and `data-motion="off"` stops motion. `--motion-scale` multiplies every duration on top.

- **Never write milliseconds, curves or zooms.** Use `motion-<surface>` for surfaces and `duration-<role>`, `duration-<role>-exit`, `delay-<role>` and `ease-enter|move|exit|feedback|drawer` for everything else. Arbitrary transitions use `calc(var(--motion-<role>) * var(--motion-scale, 1))`. `registry/fabricator/__tests__/motion-usage.test.ts` fails on fixed durations, literal curves, fixed zooms and the retired tier names.
- The `motion-<surface>` utilities hold the whole recipe: enter and exit durations and curves (exit when `data-closed`, `data-state=closed`, `data-exiting` or `data-ending-style`), the scale the surface grows from, and its slide from the trigger side. They set `--tw-duration` and `--tw-ease`, which `animate-in`/`animate-out` and every `transition*` utility read, so they time keyframes and transitions alike. Popups pair them with `origin-(--transform-origin)` and `data-open:animate-in data-open:fade-in-0 data-closed:animate-out data-closed:fade-out-0`.
- When the upstream source hard-codes a duration (sheet scrim, item, message scroller, toast, Base UI drawer), the style map sets the token with an important class; class merging keeps the source's own class otherwise. Vaul (Radix Drawer) keeps its 500ms, which its JavaScript relies on.
- The command palette marks its panel `data-motion="off"`; the dialog scrim next to it follows.
- Old names stay as aliases for consumers: `duration-fast|moderate|slow` (feedback, move, dialog) and `ease-spring`, `ease-spring-bounce` (the entrance curve). Fabricator code doesn't use them.
- Animate transform and opacity; avoid animating layout.
- Reduced motion keeps fades and drops slides, zooms, blur and the press (foundations, at every speed).

### Typography and weight

Inter. `font-medium` is 450 and `font-semibold` 550 in the Fabricator palette. **Hover changes colour (muted → foreground) and icon stroke (1.5 → 2); weight changes only for persistent state** (checked, selected, active tab, open accordion): `font-normal` → `font-semibold`. Resting labels in lists are `text-muted-foreground`; lit, selected or open ones are `text-foreground`. Optional `text-box-trim` utility centres text in fixed-height controls. For state changes that must not shift layout, use the `weight-normal` / `weight-medium` / `weight-semibold` / `weight-bold` utilities (Inter `wght` paired with `opsz`, from the foundations) with `transition-[font-variation-settings]`, e.g. `weight-normal data-checked:weight-semibold`.

### Scrollbars

Global native scrollbars are thin and low-contrast on fine pointers (in the foundations CSS). ScrollArea thumb: 4px at rest, 6px on hover, `rgb(var(--overlay)/0.08)` → `/0.12` → `/0.16` while dragging, rounded, inset 4px; the scrollbar fades in (moderate) on hover/scroll and out (moderate exit, after a moderate delay). Touch keeps native scrolling.

## Fluid hover

One `bg-hover` highlight glides to the item nearest the pointer (no dead zones in gaps; gap clicks go to the lit item). It fades in where it first appears, glides within a session, fades out when the pointer leaves. The primitive's keyboard highlight (`data-highlighted`, `aria-selected`…) moves the same highlight while the pointer is outside. A separate `bg-active` selection background slides between selected items on the move timing. Reduced motion keeps the fades and drops the travel.

### Wiring a container (override pattern)

```tsx
import { FluidHoverHighlight, FluidHoverSelection, useFluidHover, useMergedRef } from "@/registry/bases/<base>/lib/fluid-hover"

const fluid = useFluidHover<HTMLDivElement>({
  items: '[role="menuitem"]',          // selector for items inside the container
  highlighted: "[data-highlighted]",  // primitive's keyboard highlight (optional)
  selected: "[data-checked]",         // gets the sliding selection background (optional)
  axis: "y",                          // "x" for strips, "xy" for grids, "auto" follows the orientation attribute (tabs)
})
const mergedRef = useMergedRef(fluid.attach, ref)

<Primitive.Container ref={mergedRef} {...fluid.props} {...props}>
  <FluidHoverSelection selection={fluid.selection} />   {/* optional, before the highlight */}
  <FluidHoverHighlight hover={fluid.hover} />
  {children}
</Primitive.Container>
```

- The container must be `relative isolate` (put it in its style rule); overlays sit at `-z-10` inside it, under the items.
- The container gets `data-fluid-hover`; the lit item gets `data-fluid-hover-active`.
- In the style map, items keep a fallback hover (`data-highlighted:bg-hover`) and turn it off inside a fluid container: `in-data-[fluid-hover]:data-highlighted:bg-transparent`. The lit item is styled with `data-fluid-hover-active:text-foreground data-fluid-hover-active:[&_svg]:stroke-2`. Selected items with a sliding selection background drop their own background inside the container the same way.
- Override the highlight/selection look per component with `className` (e.g. tabs: `className="cn-tabs-selection"`), and add that placeholder to the component's style file.
- Use for: menus (dropdown, context, menubar), select, combobox, command, navigation menu, tabs, toggle group, sidebar menu, accordion triggers, table rows. Skip where a wrong click would hurt or items are far apart.

### Override rules

1. Start from the upstream file in `registry/bases/<base>/ui/<name>.tsx` (copy it to `registry/fabricator/<base>/ui/<name>.tsx`); keep every export, prop, variant and `data-slot`. Changes are additive.
2. Keep the diff small and container-level; style through placeholders, not inline classes.
3. Import Fabricator libs with `@/registry/bases/<base>/lib/…` (or `@/registry/bases/__base__/…` in `shared/`).
4. Add the item to `fabricatorOverrides` in `registry/fabricator/registry.ts` when it needs new registry dependencies (they apply only to bases with an override file).
5. Base UI first, then Radix (same behaviour), then React Aria. A base without an override keeps the upstream behaviour with Fabricator styling.

## Workflow

- **Live CSS preview (no build):** `/view/base-fabricator/<component>-example` (also `radix-…`, `aria-…` once built) renders the component's showcase from raw sources with the style map's CSS. Edit `registry/styles/fabricator/<component>.css`, run `bun run registry:build --examples` in `apps/web` (0.1s: assembles `style-fabricator.css` and checks coverage), and the dev server hot-reloads.
- **Compiled output (overrides, docs pages):** `scripts/build-fabricator.sh [base|radix|aria|all]` in `apps/web` rebuilds `styles/*-fabricator` under a lock. Docs pages (`/docs/components/<base>/<name>`) render the compiled Fabricator style.
- **Screenshots:** headless Chrome or `puppeteer-core` with `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`; check light and dark (`localStorage.theme`).
- Every placeholder used by the components must keep a rule in its style file (the build fails otherwise). Rules may change completely; placeholder names may not.

## Cursors

The cursor says what a press will do. Rules live in the style map, so consumers can still override them with `className`.

| Cursor                     | Where                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pointer`                  | Anything that activates on click: buttons, toggles and toggle-group items, tabs, accordion and collapsible triggers, checkboxes, radios, switches, select and combobox triggers, every menu, select, combobox and command row (and sub-menu triggers), menubar and navigation-menu triggers and links, sidebar menu buttons and actions, breadcrumb and pagination links, calendar days and caption dropdowns, dialog and sheet close buttons, the message scroller button, native selects, and Items rendered as a link or button. |
| `pointer` on labels        | Labels that name a checkable control (checkbox, switch, radio): wrapping it, placed after it, or inside the same Field.                                                                                                                                                                                                                                                                                                                                                                                                             |
| `text`                     | Text entry: inputs and textareas (native), input-OTP slots, and the combobox chips row (a click focuses its input).                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `grab` → `grabbing`        | Things you drag: slider thumbs and the drawer handle. The slider track is `pointer` (a click jumps to that value).                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `ew-resize` / `col-resize` | The sidebar rail and resizable handles.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `not-allowed`              | Disabled form controls, disabled sliders, and buttons that stay focusable while disabled (`aria-disabled`). Controls disabled with `pointer-events: none` show the cursor of what is behind them.                                                                                                                                                                                                                                                                                                                                   |
| `default`                  | Everything else: surfaces, text, popup chrome, select scroll buttons (they scroll on hover).                                                                                                                                                                                                                                                                                                                                                                                                                                        |

Upstream marks menu, select and combobox rows `cursor-default` inline. The Fabricator overrides drop that token so the style map's `cursor-pointer` applies.

## Rendering

Everything should land on whole pixels and render smoothly.

- **Text:** the foundations set grayscale anti-aliasing (`-webkit-font-smoothing: antialiased`, `-moz-osx-font-smoothing: grayscale`), `text-rendering: optimizeLegibility`, kerning, `font-optical-sizing: auto` and `font-synthesis: none` (no faux bold or italic) on `html`, and remove the tap highlight on touch.
- **No half-pixel transforms at rest:** a `translate(-50%)` lands on half pixels for odd sizes and blurs text. Dialogs and alert dialogs are centered with `inset-0 m-auto h-fit` instead; enter/exit zooms still animate `transform`, which is back to `none` at rest.
- **Fluid Hover** positions its highlight from `offsetTop`/`offsetLeft`, which are whole pixels.

## Not in the library

The Fabricator library doesn't ship controls that only restyle a raw native element. `FABRICATOR_EXCLUDED_ITEMS` in `registry.ts` leaves them out of the published registry and points dependencies at the replacement: Native Select → Select. Chart is left out for now, with the blocks built on it (Dashboard 01 and the `preview` / `preview-02` showcase blocks). The upstream styles, compiled only for the parity check, keep every upstream item.
